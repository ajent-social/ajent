## T7.2: Write the user documentation set

### Objective

Users can find complete, accurate answers for installing on any channel, understanding which tools are configured and how, what data leaves their machine, verifying a release, upgrading, and fixing every error the client can print.

### Read first

- docs/contract.md (produced by T2.1): command table, error table and file formats
- docs/adr/003-distribution-channels.md, docs/adr/004-release-signing.md, docs/adr/005-upgrade-strategy.md, docs/adr/006-client-trust-boundaries.md, docs/adr/007-harness-integration-model.md
- docs/tasks/T5.3.md, docs/tasks/T5.7.md, docs/tasks/T5.9.md and docs/tasks/T6.3.md, if present
- README.md (T7.1), if present, for consistent wording

### Scope

- `docs/install.md`
- `docs/harnesses.md`
- `docs/privacy.md`
- `docs/verifying-releases.md`
- `docs/troubleshooting.md`
- `docs/self-update.md`

### Out of scope

- `docs/upgrading.md` (T6.7), `docs/commands.md` and `docs/mcp-tools.md` (generated by T7.3), README.md (T7.1).
- Pricing, service internals, internal hostnames, internal project names and personal paths.

### Steps

1. Style: Google developer documentation style, ASCII only, sentence-case headings, second person. Put commands in code blocks with a language tag (`sh`, `powershell`).
2. `docs/install.md`: sections `## Install script (macOS and Linux)`, `## Install script (Windows)`, `## Homebrew`, `## apt` (anchor `#apt`), `## dnf` (anchor `#dnf`), `## Scoop`, `## winget`, `## Go`, `## Pin a version`, `## Custom install directory` and `## After installing`.
   - apt: download the key with `curl -fsSL https://pkg.ajent.social/gpg.key | sudo gpg --dearmor -o /usr/share/keyrings/ajent.gpg`, fetch the source file with `curl -fsSL https://pkg.ajent.social/ajent.sources | sudo tee /etc/apt/sources.list.d/ajent.sources`, then run `sudo apt update && sudo apt install ajent`.
   - dnf: `sudo curl -fsSL https://pkg.ajent.social/ajent.repo -o /etc/yum.repos.d/ajent.repo`, then `sudo dnf install ajent`.
   - Pin a version: `AJENT_VERSION=0.7.0` for both scripts.
   - Custom directory: `AJENT_INSTALL_DIR`. Skip setup with `AJENT_NO_SETUP=1`.
   - After installing: run `ajent setup`, then `ajent doctor`.
3. `docs/harnesses.md`: one `##` section per tool (Claude Code, Codex, Cursor, Gemini CLI, GitHub Copilot CLI, VS Code). Each section gives the config file location per OS, the exact entry ajent writes (a JSON example with `"command": "/path/to/ajent"` and `"args": ["mcp", "--profile", "<profile>", "--project-profile"]`), the profile name, and how to remove the entry (`ajent uninstall` or the tool's own command). Add `## Other MCP clients` (use `~/.aj/mcp-example.json`), `## Profiles` (one identity per tool per project, derived locally from a hash, so the directory path is never sent) and `## Backups and rollback`.
4. `docs/privacy.md`: sections `## What leaves your machine`, `## What never leaves your machine`, `## Where data is stored locally` (a table of the files in `~/.aj` from docs/contract.md, with their purpose), `## Retention` (30 days by default for root conversations), `## Product feedback (off by default)` (`ajent feedback show|preview|set|revoke|clear`, and exactly which fields are sent), `## Update checks` (User-Agent only; opt out with `AJENT_NO_UPDATE_CHECK=1`) and `## Repositories cannot grant access`. Each claim links to the ADR 006 section or names the test that proves it. Use the form "Tested by `TestXxx` in `internal/...`" only when the test exists. Otherwise link the ADR.
5. `docs/verifying-releases.md`: sections `## Checksums`, `## Signature` (Ed25519 over `checksums.txt`; the public key is at `https://pkg.ajent.social/ajent-release.pub` and its fingerprint is in SECURITY.md; show verification with `openssl pkeyutl -verify -pubin -inkey ajent-release.pub -rawin -in checksums.txt -sigfile checksums.txt.sig` for OpenSSL 3), `## Build provenance` (`gh attestation verify <archive> --repo ajent-social/ajent`), `## macOS notarization` (`spctl --assess --type execute -v $(command -v ajent)`) and `## Package repositories` (the GPG key URL and fingerprint placeholder).
6. `docs/troubleshooting.md`: a table with columns Error code, What it means and What to do, with one row per error code in docs/contract.md: `connection_failed`, `unauthorized`, `permission_denied`, `not_found`, `conflict`, `cursor_expired`, `rate_limited`, `service_unavailable`, `invalid_request`, `unsupported_capability`. Use the action text from the contract. Then add sections `## ajent setup did not configure my tool`, `## My tool does not see the ajent tools` (restart the tool or reload MCP servers), `## Windows: ajent is not recognized` (open a new terminal; check the user PATH), `## macOS: "cannot be opened"` and `## Collect diagnostics` (`ajent doctor`, `ajent integrations status`).
7. `docs/self-update.md`: how automatic updates work for script installs (once per 24 hours, stable releases only, signature verified, off in CI), how to turn them off, where the log is (`~/.aj/update.log`), and how package-managed installs differ. Link ADR 005 and docs/upgrading.md.
8. If a detail is not yet fixed by docs/contract.md or a task contract, write the text from the ADR and list the item in the PR body under "Needs confirmation after implementation".

### Acceptance criteria

- All six files exist and have the sections listed above.
- The troubleshooting table has one row for every error code in docs/contract.md. Check this by comparing the list of codes.
- `LC_ALL=C grep -n '[^ -~]' docs/install.md docs/harnesses.md docs/privacy.md docs/verifying-releases.md docs/troubleshooting.md docs/self-update.md` prints nothing.
- No pricing statements, internal names or personal paths. Only the hosts `ajent.social`, `pkg.ajent.social`, `github.com` and `api.github.com` appear.

### Verification

