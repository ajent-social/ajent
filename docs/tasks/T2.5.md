## T2.5: Add capability negotiation

### Objective

Operations gated on server capabilities fail fast with a clear, typed "unsupported capability" error, without ever calling the gated route, when `GET /v1/reliability` does not advertise the capability.

### Read first

- docs/interfaces.md, section `internal/api` (`UnsupportedCapabilityError`, `Capabilities`, `Require`)
- docs/contract.md section 9 (capabilities)
- internal/api/client.go (T2.4)

### Scope

Create exactly these files:

- `internal/api/capabilities.go`
- `internal/api/capabilities_test.go`

### Out of scope

- Every other file in `internal/api`.
- Command code.
- Feedback's own lenient capability lookup (T2.11).

### Steps

1. Define `type UnsupportedCapabilityError struct{ Capability string }`. Its `Error()` returns `"ajent: unsupported_capability. Server capability " + Capability + " is unavailable. Upgrade before retrying this operation."`.
2. Add unexported fields to `Client` through a separate struct embedded by pointer, so `client.go` stays untouched. Declare a package-level `var capCache sync.Map` keyed by `*Client` plus the credential server and token identity. The value is `[]string`. This avoids editing the `Client` struct owned by T2.4.
3. `Capabilities(ctx, cred)`:
   - Return the cached value when present.
   - Otherwise call `c.Do(ctx, cred, Request{Method: "GET", Route: "/v1/reliability", Timeout: 3 * time.Second, Attempts: 1, NoObserve: true}, &body)`, where `body` is `struct{ Capabilities []string`json:"capabilities"`}`.
   - On success, cache and return the list. On error, return the error and do not cache it.
4. `Require(ctx, cred, capability)`:
   - `caps, err := c.Capabilities(ctx, cred)`. If `err != nil`, return `err`.
   - If the capability is not in `caps`, return `&UnsupportedCapabilityError{Capability: capability}`.
   - Otherwise return nil.
5. Tests:
   - `TestRequirePresent`: a fake `/v1/reliability` returns `{"capabilities":["goals","group_lifecycle"]}`. `Require(..., "goals")` returns nil.
   - `TestRequireAbsent`: returns `*UnsupportedCapabilityError` with `errors.As`, and the error text is exact.
   - `TestCapabilitiesCached`: two `Require` calls make one reliability request.
   - `TestCapabilitiesErrorNotCached`: the first call returns 503 and the second returns 200. The first returns an `*Error`, the second succeeds, and there are 2 requests in total.
   - `TestGatedRouteNotCalled`: simulate a caller pattern (`if err := Require(...); err != nil { return err }; Do(gated)`). With the capability absent, `fakeserver.Requests()` contains no request to the gated path `/v1/goals`.

### Acceptance criteria

- `go test ./internal/api/... -race -count=1 -run 'Capabilit|Require|Gated'` passes.
- Genuine-red check: temporarily make `Require` return nil unconditionally. `TestRequireAbsent` and `TestGatedRouteNotCalled` must fail. Restore and report both outputs.
