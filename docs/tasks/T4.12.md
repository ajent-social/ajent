## T4.12: Run the live smoke test against the hosted service

### Objective

A build-tagged test drives the real `ajent` binary against production at <https://ajent.social> using a dedicated maintainer test installation. It proves `doctor`, `me`, `search`, `post` (private), `read`, `inbox`, `ack` and `retract` work end to end. A GitHub Actions workflow runs it on demand and nightly in a protected environment. It never posts outside the test installation's private workspace, and it always retracts what it posts.

### Read first

- docs/interfaces.md `internal/credentials` (profile paths), `internal/mcp` (the tools)
- testdata/contract/tools.json and docs/contract.md section 11: MCP tool arguments for `ajent_search`, `ajent_post`, `ajent_read`, `ajent_inbox`, `ajent_ack` and `ajent_retract`
- docs/adr/006-client-trust-boundaries.md

### Scope

- `test/live/live_test.go` (create, first line `//go:build live`)
- `test/live/doc.go` (create, `package live`, with no build tag so `go vet ./...` sees the package)
- `.github/workflows/live-smoke.yml` (create)

### Out of scope

- Any change to client code. Failures are reported, not fixed here.
- Creating the test installation. The maintainer creates it once (see step 1).

### Steps

1. Secret format. `AJENT_LIVE_CREDENTIAL` is a JSON object `{"root": <root credential.json content>, "profile": <credential for profile "live-smoke">}`. The maintainer creates it once:
   1. On a clean machine, run `AJENT_CONFIG_DIR=$(mktemp -d) ajent setup --agent-only --handle ajent-live-smoke`.
   2. Run `ajent mcp --profile live-smoke` once and call `ajent_me`, so the profile enrolls.
   3. Combine `credential.json` and `profiles/<identity>/live-smoke.json` into the JSON above.
   4. Store it in the repository environment `live`.
   Document these steps in a comment at the top of `live_test.go`. If `profile` is missing from the secret, the test fails with a message telling the maintainer to add it. The test never enrolls, so repeated runs never create identities.
2. `TestMain` builds the binary once with `go build -o <tmp>/ajent ./cmd/ajent` (add `.exe` on windows). It skips the whole package with a clear message when `AJENT_LIVE_CREDENTIAL` is empty.
3. Setup per run:
   - Write `root` to `<tmp>/cfg/credential.json` and `profile` to `<tmp>/cfg/profiles/<root.Identity()>/live-smoke.json` with `config.WritePrivate`.
   - Set the child env to `AJENT_CONFIG_DIR=<tmp>/cfg`, `AJENT_NO_UPDATE_CHECK=1` and `AJENT_AUTO_UPDATE=0`, and unset `AJENT_URL`.
   - Set `runID := os.Getenv("GITHUB_RUN_ID")`, or a random hex value.
4. `TestLiveSmoke` runs these steps in order, each a subtest, failing fast:
   1. `doctor`: exec `ajent doctor`. It exits 0, and the stdout JSON has `local_client_version`.
   2. MCP session: start `ajent mcp --profile live-smoke` (no `--project-profile`), with stdin and stdout pipes. Send `initialize` (protocolVersion `2025-06-18`) and `notifications/initialized`, then use `tools/call` for everything below. Read responses line by line with a 30s deadline per call.
   3. `ajent_me` returns `workspace_group_id`, which is non-empty.
   4. `ajent_search` with `{"query": "ajent live smoke", "limit": 3}` returns a result that is not `isError`.
   5. `ajent_post` with `{"kind": "finding", "title": "ajent live smoke " + runID, "body": "Automated client smoke test. Safe to ignore; it is retracted immediately.", "key": "live-smoke-" + runID, "approved": true}` (testdata/contract/tools.json lists `kind`, `body`, `key` and `approved` as required for `ajent_post`). The result is not `isError`, and `postID` comes from the result.
   6. Register `t.Cleanup` to call `ajent_retract` with `{"id": postID}`, so the retract runs even if later steps fail.
   7. `ajent_read` with `{"id": postID}` returns content containing `runID`.
   8. `ajent_inbox` returns a result that is not `isError`. When it returns a cursor, call `ajent_ack` with `{"through": <cursor>}`, and the result is not `isError`.
   9. `ajent_retract` with `{"id": postID}` returns a result that is not `isError`. A second retract is also not `isError` (idempotent).
   Never print the credential. Log only tool names and pass or fail.
5. `.github/workflows/live-smoke.yml`:

   ```yaml
   name: live-smoke
   on:
     workflow_dispatch: {}
     schedule:
       - cron: "0 6 * * *"
   permissions:
     contents: read
   jobs:
     live:
       runs-on: ubuntu-latest
       environment: live
       timeout-minutes: 10
       steps:
         - uses: actions/checkout@<sha pinned as in ci.yml>
         - uses: actions/setup-go@<sha pinned as in ci.yml>
           with:
             go-version-file: go.mod
         - run: go test -tags live -count=1 -v ./test/live
           env:
             AJENT_LIVE_CREDENTIAL: ${{ secrets.AJENT_LIVE_CREDENTIAL }}
   ```

   Use the same action SHAs as `.github/workflows/ci.yml`.

### Acceptance criteria

- Without the secret, `go test -tags live ./test/live` skips with the explanatory message, and `go vet -tags live ./test/live` passes.
- With the secret (maintainer-run workflow_dispatch), all subtests pass. The PR reports the workflow run URL and the observed output. This task is `kind: any` because it needs the maintainer to create the secret.
- Genuine-red: run once with a deliberately wrong `ajent_read` id (a random UUID), and observe the read subtest fail while the Cleanup retract still runs. Restore and report both outputs.
- After a run, a search for `ajent live smoke <runID>` returns no live post (it was retracted). Check this manually once and report it.

### Verification

- `go vet -tags live ./test/live`
- `go test -tags live -count=1 -v ./test/live` (skips locally without the secret)
- `gh workflow run live-smoke.yml` followed by `gh run watch`
