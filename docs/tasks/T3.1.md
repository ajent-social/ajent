## T3.1: Build the stdio JSON-RPC transport

### Objective

`internal/mcp` has a JSON-RPC 2.0 transport that reads newline-delimited messages from an `io.Reader`, dispatches them to a `Dispatcher`, and writes exactly one JSON line per response to an `io.Writer`. A reviewer can run `go test ./internal/mcp -run TestServeRPC` and see every protocol edge case (initialize negotiation, ping, unknown method, malformed input, oversized input, notifications) handled with nothing but JSON-RPC on the output stream.

### Read first

- docs/interfaces.md, section "internal/mcp", the part marked "T3.1". Implement exactly those identifiers.
- docs/design.md, the "Invariants" section (MCP stdout carries JSON-RPC messages only).
- docs/adr/006-client-trust-boundaries.md.
- The MCP specification lifecycle page: <https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle>

### Scope

Create only these files:

- `internal/mcp/jsonrpc.go`
- `internal/mcp/jsonrpc_test.go`
- `testdata/mcp/transport/basic.in.jsonl`
- `testdata/mcp/transport/basic.out.jsonl`
- `testdata/mcp/transport/errors.in.jsonl`
- `testdata/mcp/transport/errors.out.jsonl`

### Out of scope

- The tool registry, session, envelope, tool handlers and the `ajent mcp` command (T3.2 and later).
- Building the `initialize` result body. The Dispatcher does that (T3.2). This task only calls `Dispatcher.Initialize` and exports `NegotiateProtocol`.
- Any import of another `internal/` package. This file must compile with only T1.1 in place.

### Steps

1. In `internal/mcp/jsonrpc.go` (package `mcp`, SPDX header `// SPDX-License-Identifier: Apache-2.0`), declare exactly: `MaxLineBytes = 1 << 20`; `RPCError{Code int "json:\"code\""; Message string "json:\"message\""}` with `Error() string` returning `fmt.Sprintf("jsonrpc %d: %s", e.Code, e.Message)`; the five code constants `CodeParseError = -32700`, `CodeInvalidRequest = -32600`, `CodeMethodNotFound = -32601`, `CodeInvalidParams = -32602`, `CodeInternalError = -32603`; the `Dispatcher` interface; `SupportedProtocols = []string{"2024-11-05", "2025-03-26", "2025-06-18", "2025-11-25"}`; and `NegotiateProtocol(requested string) string`. It returns `requested` if it is in `SupportedProtocols`, else the last element (`"2025-11-25"`).
2. Define an unexported request type: `type request struct { JSONRPC string "json:\"jsonrpc\""; ID json.RawMessage "json:\"id\""; Method string "json:\"method\""; Params json.RawMessage "json:\"params\"" }`. A message is a notification when the `id` member is absent (`len(ID) == 0`). An explicit `"id": null` is treated as a request with a null id.
3. Implement `ServeRPC(ctx context.Context, r io.Reader, w io.Writer, d Dispatcher) error`:
   1. Use `bufio.NewReaderSize(r, 64*1024)` and read with `ReadSlice('\n')` in a loop, accumulating into a buffer. As soon as the accumulated length exceeds `MaxLineBytes`, stop accumulating, discard bytes through the next `'\n'` (or EOF), and write the parse-error response from step 3.3. Never hold more than `MaxLineBytes + 64 KiB` in memory.
   2. Trim `\r\n` and surrounding ASCII whitespace. Skip empty lines silently.
   3. On invalid JSON, a JSON value that is not an object, or an oversized line, write `{"jsonrpc":"2.0","id":null,"error":{"code":-32700,"message":"Parse error"}}`.
   4. If the `id` member is absent, treat the message as a notification. Do not call the Dispatcher for `notifications/initialized` or any `notifications/*`, and write nothing. Covering `notifications/cancelled` is not required.
   5. If `jsonrpc` is not `"2.0"` or `method` is empty, write an error with code -32600 and message `"Invalid Request"`, echoing the id.
   6. Dispatch on `method`. `"initialize"` calls `d.Initialize(ctx, params)`. `"ping"` returns result `{}` (an empty JSON object) without calling the Dispatcher. `"tools/list"` calls `d.ListTools(ctx)`. `"tools/call"` calls `d.CallTool(ctx, params)`. Anything else returns error -32601 with message `"Method not found"`.
   7. Map errors. If the Dispatcher returns an error `e` where `errors.As(e, &*RPCError)` succeeds, write that code and message. For any other error, write -32603 with message `"Internal error"`. Never include Go error text in the response.
   8. On success, write `{"jsonrpc":"2.0","id":<echoed raw id>,"result":<result>}`. Marshal with an `encoding/json` `Encoder` that has `SetEscapeHTML(false)`, so each response is exactly one line ending in `\n`. Build the whole line in a `bytes.Buffer` and write it with a single `w.Write`.
   9. After a successful `tools/call` write, call the `after` func if it is non-nil. If the write failed, do not call it, and return the write error.
   10. Process messages sequentially, one at a time. Return `nil` on EOF. Return `ctx.Err()` if the context is cancelled between messages.
4. Keep all logging out of `w`. This file does no logging at all.
5. Write the fixtures. `testdata/mcp/transport/basic.in.jsonl` has one message per line, in this order:
   1. initialize with id 1 and protocolVersion "2024-11-05".
   2. initialize with id 2 and "2025-03-26".
   3. initialize with id 3 and "2025-06-18".
   4. initialize with id 4 and "2025-11-25".
   5. initialize with id 5 and "1999-01-01".
   6. `{"jsonrpc":"2.0","method":"notifications/initialized"}`.
   7. ping with id "p1" (a string id).
   8. tools/list with id 6.
   9. tools/call with id 7.

   `basic.out.jsonl` has the exact expected output lines. `errors.in.jsonl` has:
   1. `not json`.
   2. `[1,2]`.
   3. `{"jsonrpc":"1.0","id":8,"method":"ping"}`.
   4. `{"jsonrpc":"2.0","id":9,"method":"resources/list"}`.
   5. An empty line.
   6. `{"jsonrpc":"2.0","id":10,"method":"tools/call","params":{"name":"boom"}}`, where the fake Dispatcher returns a plain `errors.New("secret detail")`.

   `errors.out.jsonl` has the expected lines. Note there is none for the empty line.
6. In `jsonrpc_test.go`, define `fakeDispatcher`. Its `Initialize` decodes `{"protocolVersion":string}` and returns `map[string]any{"protocolVersion": NegotiateProtocol(v)}`. `ListTools` returns `map[string]any{"tools": []any{}}`. `CallTool` returns `map[string]any{"ok": true}` and an `after` func that increments a counter, except for the name "boom", where it returns `errors.New("secret detail")`. Write these tests:
   - `TestServeRPCBasicTranscript`: feed `basic.in.jsonl` and compare the output line-by-line with `basic.out.jsonl`. Compare as decoded JSON values with `reflect.DeepEqual`, so key order does not matter.
   - `TestServeRPCErrorTranscript`: the same with the errors files. Also assert the output does not contain `secret detail`.
   - `TestServeRPCOversizedLine`: one line of `MaxLineBytes+10` bytes of `a`, followed by a valid ping. Expect exactly two output lines: the -32700 response with id null, then the ping result.
   - `TestServeRPCNotificationWritesNothing`: only notifications in, zero bytes out.
   - `TestServeRPCAfterRunsOnlyAfterWrite`: one writer that fails on write (a custom `io.Writer` returning an error), and one writer that succeeds. The after counter is 0 in the first case and 1 in the second.
   - `TestNegotiateProtocol`: a table covering all four supported versions, `""` and `"2030-01-01"` (the last two expect `"2025-11-25"`).
   - `TestServeRPCOutputIsOnlyJSONLines`: every output line from both transcripts parses as a JSON object with `"jsonrpc":"2.0"`.
7. Run gofmt, go vet and golangci-lint on the package.

### Acceptance criteria

- All tests listed in step 6 pass on ubuntu, macos and windows CI.
- `go list -deps ./internal/mcp` shows no `github.com/ajent-social/ajent/internal/...` package other than `internal/mcp` itself, at the time this task merges.
- The response to a non-RPCError never contains the Go error text.
- Genuine-red check: temporarily change `NegotiateProtocol` to always return `"2024-11-05"`. Observe `TestNegotiateProtocol` and `TestServeRPCBasicTranscript` fail. Restore it and observe them pass. Then temporarily remove the oversized-line guard (accumulate without limit). Observe `TestServeRPCOversizedLine` fail. Restore it. Report both failing and passing outputs in the PR.
