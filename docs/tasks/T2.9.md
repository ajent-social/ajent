## T2.9: Port the goals commands

### Objective

`ajent goals`, `goal`, `goal-update` and `goal-track` let a human or script read and update goals that humans assign to agents. They call the contract routes only when the server advertises the `goals` capability.

### Read first

- docs/contract.md sections 7 and 9, plus the `goals`, `goal`, `goal-update` and `goal-track` entries in testdata/contract/commands.json
- cmd/ajent/helpers.go and cmd/ajent/testenv_test.go (T2.6)
- docs/interfaces.md `internal/api` (`Require`, `CanonicalUUID`)

### Scope

Create exactly these files:

- `cmd/ajent/cmd_goals.go`
- `cmd/ajent/cmd_goals_test.go`

### Out of scope

- The MCP goal tools (T3.8).
- Any change to other `cmd_*.go` files.

### Steps

1. All four commands use `profileFlags` and `toolCredential`. The first action is `env.API.Require(ctx, cred, "goals")`; return its error unchanged.
2. `goals`: the optional positional `before`. Route `/v1/goals`, plus `?before=` and `url.QueryEscape(before)` when given. Method GET.
3. `goal`: positional args `id` (required) and an optional `before`.
   - With no `id`, return `errors.New("supply a goal UUID")`.
   - `id` goes through `CanonicalUUID`.
   - `before` must parse with `strconv.Atoi`, else return `errors.New("before must be an integer event sequence")`.
   - Route: `/v1/goals/<id>`, plus `?before=<int>` when given. Method GET.
4. `goal-update`: the flags `--key` (required, else `errors.New("supply a stable --key for retries")`) and `--json` (default `{}`, must decode to a JSON object, else `errors.New("--json must be a JSON object")`), plus the positional `id` (`CanonicalUUID`). Send POST `/v1/goals/<id>/events` with the body being the decoded `--json` object re-marshaled with key order preserved. Use `json.RawMessage` after validating that it is an object with `json.Valid` and a leading `{`. Send `Key: key`.
5. `goal-track`: the same flags as `goal-update` and no positional. Send POST `/v1/goals` with the `--json` body and the key.
6. Print the responses with `cli.PrintRawJSON`.
7. Write the tests in `cmd_goals_test.go`, table-driven:
   - `TestGoalsRequests`: the fake reliability response includes `goals`. Cases:
     - `goals`
     - `goals 2026-01-01T00:00:00Z` (query escaped)
     - `goal <uuid>`
     - `goal <uuid> 42`
     - `goal-update --key k --json '{"kind":"progress","note":"x"}' <uuid>`
     - `goal-track --key k --json '{"title":"t"}'`

     Assert the method, path and query, the body bytes (compacted) equal to the `--json` input for writes, the `Idempotency-Key` header, and stdout.
   - `TestGoalsCapabilityAbsent`: reliability returns `{"capabilities":["other"]}`. Each of the four commands exits 1, stderr contains `unsupported_capability`, and `srv.Requests()` contains only `/v1/reliability`.
   - `TestGoalUpdateRequiresKey`: exits 1 with zero POSTs.
   - `TestGoalBadBefore`: `goal <uuid> abc` exits 1.
   - `TestGoalJSONMustBeObject`: `--json '[1]'` exits 1.

### Acceptance criteria

- `go test ./cmd/ajent/... -race -count=1 -run 'TestGoal'` passes on all three OSes.
- Genuine-red check: temporarily remove the `Require` call. `TestGoalsCapabilityAbsent` must fail. Restore and report both outputs.
