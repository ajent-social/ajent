## T4.15: Write the VS Code integration

### Objective

When VS Code's user settings directory exists, `ajent integrations sync` adds `servers.ajent` with `"type": "stdio"` to the VS Code user `mcp.json`, using the correct per-OS path. Other keys are preserved byte-for-byte, and a second run is byte-identical. This lets GitHub Copilot in VS Code use Ajent.

Decision (orchestrator, from the T2.1 contract freeze): Go writes the harness `env` block only when the config directory or credential file is non-default, while the Python client always wrote both variables (docs/contract.md section 9). Any existing `ajent` entry whose command runs `ajent mcp` or `client.py mcp` counts as ajent-owned (`Owned` in T4.17) and is replaced, so migration, post-upgrade sync and uninstall work on Python-era entries. This intentionally differs from the reference, which left any differing existing entry unchanged and, for Claude Code and Codex, kept any registration that `mcp get ajent` found. Entries that are not owned are still never modified.

### Steps

1. `type vscodeWriter struct{}` registered in `init()`. `Target()` returns `Target{Name: "vscode", Profile: "copilot-vscode"}`.
2. `userDir(p Params) string`:
   - `p.GOOS == "darwin"`: `filepath.Join(p.Home, "Library", "Application Support", "Code", "User")`.
   - `p.GOOS == "windows"`: `appdata := p.Getenv("APPDATA")`. If empty, use `filepath.Join(p.Home, "AppData", "Roaming")`. Return `filepath.Join(appdata, "Code", "User")`.
   - Otherwise (linux and others): `base := p.Getenv("XDG_CONFIG_HOME")`. If empty or not absolute, use `filepath.Join(p.Home, ".config")`. Return `filepath.Join(base, "Code", "User")`.
3. `configPath(p) = filepath.Join(userDir(p), "mcp.json")`. `Detect(p)` is true when `userDir(p)` is an existing directory. `Paths(p)` is `[]string{configPath(p)}`.
4. `Apply(ctx, p)`: if not detected, return `skipped`. `e := Entry(p, "copilot-vscode")` and `e["type"] = "stdio"`. Then `MergeJSONServer(configPath(p), "servers", e)`. Map errors exactly like the other JSON writers:
   - `ErrUnparseable` gives `incomplete` with detail `config has comments or is not plain JSON; left unchanged`.
   - `ErrForeignEntry` gives `incomplete` with detail `an existing ajent entry with other settings was preserved`.
   - `config.ErrSymlink` gives `incomplete` with detail `config is a symlink; left unchanged`.
   - Otherwise `changed` gives `configured`, and no change gives `unchanged`.
5. `Remove(ctx, p)`: `RemoveJSONServer(configPath(p), "servers")`. Owned gives `removed`, foreign gives `unchanged`.
6. Golden cases under `testdata/integrations/vscode/<case>/before|after/`. The fixture tree mirrors the home for linux (`.config/Code/User/mcp.json`). The test remaps the path per GOOS by computing `userDir` against the temp home:
   - `fresh-dir`: after is `{"servers": {"ajent": {"args": [...], "command": "/opt/ajent/bin/ajent", "type": "stdio"}}}` (2-space indent, keys sorted as T4.17 specifies).
   - `foreign-servers`: before has `inputs: []` first and `servers.github` with `type: "http"`. Both are byte-preserved. `ajent` is appended last.
   - `python-entry`: `servers.ajent` with python3 and `client.py` is replaced in place.
   - `current`: unchanged.
7. Tests:
   - `TestVSCodeUserDir` (table): darwin; windows with APPDATA set; windows with APPDATA empty; linux with XDG_CONFIG_HOME `/x/cfg`; linux with a relative XDG_CONFIG_HOME, which falls back to `~/.config`.
   - `TestVSCodeGolden`: runs every case with `GOOS: runtime.GOOS`, placing the fixture file at `userDir(p)`.
   - `TestVSCodeSecondRunUnchanged`, `TestVSCodeNotDetected`, `TestVSCodeJSONCPreserved`, `TestVSCodeForeignEntryPreserved`, `TestVSCodeRemove`.

### Acceptance criteria

- All tests pass with `-race` on ubuntu, macos and windows.
- Genuine-red: swap the `darwin` and default branches in `userDir`, then observe `TestVSCodeUserDir` fail. Restore and report both outputs.
- Genuine-red: omit `e["type"] = "stdio"`, then observe `TestVSCodeGolden/fresh-dir` fail. Restore.
