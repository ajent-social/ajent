## T4.16: Write the Codex integration

### Objective

When the `codex` CLI is installed, `ajent integrations sync` registers the Ajent MCP server through `codex mcp add`, pointing at the stable ajent binary with profile `codex`. Reruns change nothing. Owned outdated entries are replaced. Foreign entries are preserved.

Decision (orchestrator, from the T2.1 contract freeze): Go writes the harness `env` block only when the config directory or credential file is non-default, while the Python client always wrote both variables (docs/contract.md section 9). Any existing `ajent` entry whose command runs `ajent mcp` or `client.py mcp` counts as ajent-owned (`Owned` in T4.17) and is replaced, so migration, post-upgrade sync and uninstall work on Python-era entries. This intentionally differs from the reference, which left any differing existing entry unchanged and, for Claude Code and Codex, kept any registration that `mcp get ajent` found. Entries that are not owned are still never modified.

### Steps

1. `type codexWriter struct{}` registered in `init()`. `Target()` returns `Target{Name: "codex", Profile: "codex"}`.
2. `Detect(p)`: `LookPath("codex")` succeeds.
3. `Paths(p)`: `[filepath.Join(p.Home, ".codex", "config.toml")]`.
4. `want := Entry(p, "codex")`.
5. `current(ctx) (map[string]any, bool)`: `out, err := Run(ctx, "codex", "mcp", "get", "ajent", "--json")`. If `err != nil`, the entry is absent (`nil, false`). Otherwise unmarshal `out` into `any`. If that fails, return `map[string]any{"command": "<unknown>"}, true`, which counts as foreign. Search the decoded value depth-first for the first object that has a string `command`. Return a map with `command`, `args` (the `[]any` found next to it, or empty) and `env` (the object next to it, or absent).
6. `Apply(ctx, p)`:
   - If present and `SameEntry(existing, want)` (missing env equals empty env), the status is `unchanged`.
   - If present and `!Owned(existing)`, the status is `incomplete` with detail `an existing ajent entry with other settings was preserved`.
   - If present and owned, run `Run(ctx, "codex", "mcp", "remove", "ajent")` first.
   - Add with argv built exactly as: `["mcp", "add"]`, then for each env key in sorted order `"--env", key + "=" + value`, then `"ajent", "--", p.Binary, "mcp", "--profile", "codex", "--project-profile"`. Call `Run(ctx, "codex", argv...)`.
   - On any Run error, the status is `incomplete` with detail `setup incomplete; existing settings preserved, see <ConfigDir>/mcp-example.json`. Never include Run output.
   - On success, the status is `configured`.
7. `Remove(ctx, p)`: owned gives `codex mcp remove ajent` and status `removed`. Foreign gives `unchanged` with detail `foreign ajent entry preserved`. Absent gives `unchanged`.
8. Tests use a fake `Run` that stores one entry in memory, answers `mcp get ajent --json` with `{"name":"ajent","transport":{"type":"stdio","command":...,"args":[...],"env":{...}}}` or exits with an error when absent, and records argv:
   - `TestCodexAddArgv`: default config dir. The argv equals `codex mcp add ajent -- /opt/ajent/bin/ajent mcp --profile codex --project-profile`.
   - `TestCodexAddArgvWithEnv`: custom config dir and credential file. The argv contains `--env AJENT_CONFIG_DIR=/x/c --env AJENT_CREDENTIAL_FILE=/x/c/cred.json` before `ajent`.
   - `TestCodexUnchangedSecondRun`.
   - `TestCodexReplacesPythonEntry`.
   - `TestCodexForeignPreserved`.
   - `TestCodexUnparseableGetIsForeign`: get returns `not json` with success. No mutating calls.
   - `TestCodexCLIFailureNoOutputLeak`.
   - `TestCodexRemove`.

### Acceptance criteria

- All tests pass with `-race` on all three OSes.
- Genuine-red: sort the env flags after `ajent` instead of before, then observe `TestCodexAddArgvWithEnv` fail. Restore and report both outputs.
- Genuine-red: treat an unparseable `get` output as absent, then observe `TestCodexUnparseableGetIsForeign` fail. Restore.
