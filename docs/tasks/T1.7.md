## T1.7: Configure repository settings

### Objective

The GitHub repository `ajent-social/ajent-client` has its description, topics and homepage set. Private vulnerability reporting and Discussions are enabled. Only squash and rebase merges are allowed. `main` is protected with linear history and required status checks. The repository stays private until E8.

### Read first

- docs/plan.md, Appendix A (description, topics, homepage)
- docs/tasks/T1.4.md and docs/tasks/T1.5.md (required check names)

### Scope

- `scripts/repo-settings.sh` (an idempotent script that applies the settings with `gh api`)
- `scripts/repo-settings_check.sh` (verifies the settings and exits non-zero on drift)
- No other files. Repository settings live on GitHub.

### Out of scope

- Changing repository visibility. It stays private until E8.
- The social preview image (T7.4).
- Creating other repositories (T5.0).

### Steps

1. Confirm access with `gh auth status` and `gh api repos/ajent-social/ajent-client --jq .permissions.admin`. The second command must print `true`. If it does not, stop and report "needs admin token".
2. `scripts/repo-settings.sh` (POSIX `sh`, `set -eu`, SPDX header) runs:
   - `gh api -X PATCH repos/ajent-social/ajent-client -f description='Give every coding agent you run a shared, private memory of checked findings. One-line install for Claude Code, Codex, Cursor, Gemini CLI, GitHub Copilot and VS Code. Open-source CLI and MCP server.' -f homepage='https://ajent.social' -F has_discussions=true -F has_wiki=false -F allow_merge_commit=false -F allow_squash_merge=true -F allow_rebase_merge=true -F delete_branch_on_merge=true -F allow_auto_merge=true`
   - `gh api -X PUT repos/ajent-social/ajent-client/topics -f 'names[]=mcp' -f 'names[]=model-context-protocol' -f 'names[]=mcp-server' -f 'names[]=claude-code' -f 'names[]=codex' -f 'names[]=cursor' -f 'names[]=gemini-cli' -f 'names[]=github-copilot' -f 'names[]=ai-agents' -f 'names[]=coding-agents' -f 'names[]=agent-memory' -f 'names[]=developer-tools' -f 'names[]=cli' -f 'names[]=golang'`
   - `gh api -X PUT repos/ajent-social/ajent-client/private-vulnerability-reporting`
   - Branch protection, with the body passed through `--input -` from a heredoc:

     ```json
     {
       "required_status_checks": {"strict": true, "contexts": ["format", "vet", "lint", "test (ubuntu-latest)", "test (macos-latest)", "test (windows-latest)", "vuln", "gitleaks", "leak-scan", "dco"]},
       "enforce_admins": false,
       "required_pull_request_reviews": null,
       "restrictions": null,
       "required_linear_history": true,
       "allow_force_pushes": false,
       "allow_deletions": false
     }
     ```

     to `gh api -X PUT repos/ajent-social/ajent-client/branches/main/protection --input -`.
   - If `main` does not exist yet (no commits), the protection call returns 404. In that case print `main not found; rerun after the first push` and continue. Exit 0.
3. Private repositories on the free plan may reject branch protection with 403 ("Upgrade to GitHub Pro"). Catch that response, print `branch protection unavailable while private; rerun at E8 after the repository is public`, and exit 0. Record the outcome in the PR body. The E8 planning task must rerun this script.
4. `scripts/repo-settings_check.sh` reads back `gh api repos/ajent-social/ajent-client --jq '{d:.description,h:.homepage,disc:.has_discussions,merge:.allow_merge_commit}'` and `gh api repos/ajent-social/ajent-client/topics --jq '.names|length'`. It exits 1 if the description differs from the script's string, the homepage is not `https://ajent.social`, Discussions are off, merge commits are allowed, or fewer than 14 topics are set.
5. Run the setup script, then the check script.

### Acceptance criteria

- `scripts/repo-settings_check.sh` exits 0.
- `gh api repos/ajent-social/ajent-client --jq .private` still prints `true`.
- Branch protection is applied, or the PR body records the exact 403 or 404 message and the deferral to E8.
- Genuine-red check: temporarily run `gh api -X PATCH repos/ajent-social/ajent-client -f homepage=https://example.com`, run the check script and observe exit 1. Rerun the setup script and observe that the check script exits 0. Report both outputs.

### Verification

```bash
sh scripts/repo-settings.sh
sh scripts/repo-settings_check.sh; echo exit=$?
gh api repos/ajent-social/ajent-client --jq '.description, .homepage, .has_discussions, .private'
gh api repos/ajent-social/ajent-client/topics --jq .names
```
