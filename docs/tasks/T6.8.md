## T6.8: Write the upgrade end-to-end test

### Objective

A black-box test on ubuntu, macos and windows installs `ajent` version N-1 as a script install with fake harness configurations, then triggers the session-start hook. It proves:

- The detached auto-update replaces the binary with version N from a local fake release server.
- The post-upgrade sync runs once and harness configs still launch a working `ajent mcp`.
- Credentials stay byte-identical.
- A tampered N+1 release is refused, and the binary stays at N.

### Read first

- docs/adr/005-upgrade-strategy.md
- docs/tasks/T6.2.md (fakerelease: `New`, `AddRelease`, `BuildAssets`, `API`, `FallbackURL`), T6.3.md, T6.4.md, T6.6.md, T5.3.md (`extraKeyB64`, keygen)
- docs/tasks/T4.2.md (hook), docs/tasks/T4.17.md (Cursor-style JSON entries), docs/tasks/T3.2.md (`ajent mcp` initialize)

### Scope

Create only:

- `test/e2e/upgrade_test.go` (package `e2e`, build tag `e2e`)
- `test/e2e/upgrade_helpers_test.go` (package `e2e`, build tag `e2e`). Do not create or edit `test/e2e/main_test.go` or `mcp_test.go` (owned by T3.7), and do not declare `TestMain`: T3.7's `TestMain` runs for the whole package. Prefix every helper you declare with `upgrade` (for example `upgradeModuleRoot`, `upgradeBuild`) so no name can collide with T3.7's helpers, whichever lands first.
- `.github/workflows/e2e-upgrade.yml`

### Out of scope

- Changes to production code. If the test exposes a defect, report it with the failing output and file an issue titled `e2e-upgrade: <symptom>`. Do not fix it in this task.

### Steps

1. `//go:build e2e` at the top of each file. The run command is `go test -tags e2e ./test/e2e -run TestUpgrade -count=1 -timeout 10m`.
2. Setup in `TestUpgrade`:
   1. Key: `pub, priv, _ := ed25519.GenerateKey(rand.Reader)`, then `pubB64 := base64.StdEncoding.EncodeToString(pub)`.
   2. Build three binaries into `t.TempDir()` with `go build -o <path> -ldflags "-X github.com/ajent-social/ajent/internal/version.Version=<v> -X github.com/ajent-social/ajent/internal/update.extraKeyB64=<pubB64>" github.com/ajent-social/ajent/cmd/ajent` for versions `0.7.0` (N-1), `0.7.1` (N) and `0.7.2` (N+1). Add `.exe` on windows.
   3. Start `fr := fakerelease.New(t)`. `fr.AddRelease("0.7.1", false, fakerelease.BuildAssets(t, "0.7.1", runtime.GOOS, runtime.GOARCH, <N bytes>, priv))`.
   4. Isolated environment: `home := t.TempDir()`, `cfg := filepath.Join(home, ".aj")`, `bin := filepath.Join(home, ".local", "bin", "ajent"[+".exe"])`. Copy N-1 to `bin`. Write `cfg/install.json` as `{"method":"script","version":"0.7.0","path":"<bin>","installed_at":"<now>"}`. Write `cfg/credential.json` with a fixture credential `{"server":"http://127.0.0.1:1","token":"aj_0000000000000000_test","handle":"e2e"}` and mode 0600, and record its bytes. Write a Cursor config at `home/.cursor/mcp.json`: `{"mcpServers":{"other":{"command":"x"},"ajent":{"command":"<home>/old/ajent","args":["mcp","--profile","cursor","--project-profile"]}}}`, and create `cfg/integration-status.json` containing `{}` so post-upgrade applies.
   5. Env for every exec: a clean list containing `HOME=<home>`, `USERPROFILE=<home>`, `AJENT_CONFIG_DIR=<cfg>`, `AJENT_UPDATE_API=<fr.API()>`, `AJENT_UPDATE_FALLBACK_URL=<fr.FallbackURL()>`, `PATH=<dir of bin>` plus the OS system dirs (so no real `claude` or `codex` binary is found), plus `APPDATA` and `LOCALAPPDATA` under home on windows. Explicitly exclude `CI` and `AJENT_AUTO_UPDATE`, even though CI sets `CI`.
3. Phase A, auto-update:
   1. Run `bin hook session-start` with that env and assert exit 0.
   2. Poll up to 60s, every 500ms, until `bin version --json` reports `0.7.1`.
   3. Assert `cfg/update.log` contains `auto-run: updated 0.7.0 -> 0.7.1`.
   4. Assert the credential file bytes are unchanged.
4. Phase B, post-upgrade sync:
   1. Run `bin hook session-start` again.
   2. Poll up to 60s until `state.json` has `seen_version` equal to `0.7.1` and the Cursor entry `command` equals `bin` (compare with `filepath.EvalSymlinks` on both sides).
   3. Assert the `other` server entry is preserved byte for byte.
   4. Run a third hook. Assert no new backup directory appears under `cfg/backups` (the sync ran exactly once).
5. Phase C, the harness entry still works: spawn the Cursor entry's `command` with its `args` and the same env, write `{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"e2e","version":"0"}}}\n` to stdin, and read one line. It decodes to a result with `serverInfo.name == "ajent"` and `serverInfo.version == "0.7.1"`. Close stdin and wait for exit.
6. Phase D, tampered N+1 is refused:
   1. Register `0.7.2` with `BuildAssets` for the N+1 binary, then corrupt the signature asset: replace `checksums.txt.sig` with a signature from a different key.
   2. Reset `state.json`'s `last_auto_update` to zero via JSON edit so the hook is due.
   3. Run the hook, wait up to 30s for `update.log` to contain `auto-run: failed`, and assert `bin version` is still `0.7.1`.
   4. Also run `bin update` directly. It exits 1, and stderr mentions the signature.
7. Phase E, opt-out: set `AJENT_AUTO_UPDATE=0`, register a valid `0.7.3`, reset `last_auto_update`, and run the hook. Wait 10s, then assert the version is still `0.7.1` and `update.log` has no new `auto-run` line.
8. Cross-OS notes:
   - On windows, the running exe is renamed aside. After phase A, assert `bin + ".old"` either does not exist or is removed after the next command run.
   - Kill any lingering detached processes in `t.Cleanup` by reading a PID list. If there is no PID tracking, wait until the `update.log` last line is final, then allow `t.TempDir` cleanup to retry. Use `t.Cleanup` with retries on windows for file locks, up to 10 tries every 500ms.
9. `.github/workflows/e2e-upgrade.yml`: on `pull_request` with paths `internal/update/**`, `cmd/ajent/**`, `internal/integrations/**`, `test/e2e/**`, plus `workflow_dispatch`. Matrix `ubuntu-latest`, `macos-latest`, `windows-latest`. Steps: checkout, setup-go (SHA-pinned), `go test -tags e2e ./test/e2e -run TestUpgrade -count=1 -timeout 10m -v`. `permissions: contents: read`.

### Acceptance criteria

- `e2e-upgrade.yml` is green on all three OSes. Report the run URL, and quote each phase's key log lines from `-v` output.
- `go vet -tags e2e ./test/e2e` and `gofmt -l test` are clean, and `actionlint` passes.
- Genuine-red: temporarily comment out the `VerifyChecksums` call in `internal/update/apply.go` on a local branch and run the test. Phase D fails because the version becomes 0.7.2. Restore it and report both outputs. Never commit the break.
