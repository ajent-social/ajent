## T3.8: Implement the goals tools

### Objective

The four goals tools (`ajent_goals`, `ajent_goal`, `ajent_goal_update`, `ajent_goal_track`) work against the fake server when the server advertises the `goals` capability. They fail cleanly with `unsupported_capability`, without calling any goal route, when it does not. Large goal reads come back as fragments carrying `snapshot_version`, and every goal result carries the `authority_model` statement.

### Read first

- docs/interfaces.md, section "internal/mcp".
- docs/contract.md sections 9 and 11 (goal tools and "Envelope") (T2.1).
- testdata/contract/tools.json entries for the four goals tools.
- `internal/mcp/compact.go` (T3.3), which provides `compactRead`.

### Scope

Create only:

- `internal/mcp/tools_goals.go`
- `internal/mcp/tools_goals_test.go`
- `testdata/mcp/goal_large.json`

### Out of scope

- Envelope changes. `authority_model` is added by `Envelope` (T3.2) for any tool name starting with `ajent_goal`. Only verify it here.
- CLI goals commands (T2.9).

### Steps

1. In `init()`, call `Handle` for the four tools. Each handler calls `c, err := s.Credential(ctx)` and then `s.API.Require(ctx, c, "goals")` before any goal request.
2. `ajent_goals`: GET `/v1/goals`, plus `?before=<url.QueryEscape(before)>` when `before` is non-empty. Return the response unchanged. It is not list-compacted, matching the reference.
3. `ajent_goal`: build a query with `before` and `version` when they are present and non-zero, encoded with `url.Values.Encode()`. GET `/v1/goals/<uuid id>` plus `?query` when the query is non-empty. Return `Result{compactRead("ajent_goal", args, resp, s.Cache, s.Scope)}`.
4. `ajent_goal_track`: the body is all args except `key`. Default `priority` to `"normal"` when absent. POST `/v1/goals` with `Key: args.key`.
5. `ajent_goal_update`: the body is all args except `id` and `key`. POST `/v1/goals/<uuid id>/events` with `Key: args.key`. Encode integer fields (`version`) as JSON integers.
6. Write `testdata/mcp/goal_large.json`: a goal response with `goal.version = 7` and enough events that its JSON exceeds 11,000 bytes.
7. Tests:
   - `TestGoalsToolsRequests`: a table over the four tools asserting the method, path, query, `Idempotency-Key` and decoded body.
   - `TestGoalsCapabilityAbsent`: for each tool, with `/v1/reliability` lacking `goals`, the handler returns `*api.UnsupportedCapabilityError`, and zero requests hit any `/v1/goals` path.
   - `TestGoalTrackDefaultsPriority`.
   - `TestGoalReadFragmentsCarrySnapshotVersion`: uses the large fixture. The first fragment has `snapshot_version: 7` and the guidance text, and following `next_offset` reconstructs the text.
   - `TestGoalEnvelopeHasAuthorityModel`: run through the Session dispatcher (the T3.2 test helper, or `Serve` with a one-line transcript). The text contains `"authority_model"`.
8. Run gofmt, go vet (including GOOS=windows) and golangci-lint.

### Acceptance criteria

- All step 7 tests pass with `-race` on ubuntu, macos and windows.
- Genuine-red check: temporarily remove the `Require(..., "goals")` call. Observe `TestGoalsCapabilityAbsent` fail with a recorded `/v1/goals` request, then restore it. Report both outputs.
