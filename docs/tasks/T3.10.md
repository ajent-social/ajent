## T3.10: Add the skill search MCP tools

### Objective

`ajent mcp` offers `ajent_skills_search` and `ajent_skills_get`, so an agent can find a reviewed skill for its task and load its verified instructions in bounded fragments. The tools use no Ajent credential and fail with clear, specific isError payloads.

### Read first

- docs/contract.md sections 11 (envelope, validation) and 14 (these tools, their exact definitions and error payloads).
- docs/interfaces.md sections "internal/mcp" (including `ToolError`) and "internal/skills (T3.9)".
- `internal/mcp/registry.go`, `serve.go` and `envelope.go` (T3.2), `internal/skills` and `internal/testutil/fakeskills` (T3.9).

### Scope

- `internal/mcp/tools_skills.go`
- `internal/mcp/tools_skills_test.go`

### Out of scope

- Editing `defs.go`, `serve.go` or any other T3.2 file. If `ToolError` mapping is missing from `serve.go`, stop and report BLOCKED on T3.2.
- `testdata/contract/` (the skill tools are Go-only and are not in tools.json).
- The CLI command (T3.11).

### Steps

1. In `init()`, call `Register` for `ajent_skills_search`, then `ajent_skills_get`, using the description, inputSchema (as a backquoted `json.RawMessage` literal) and annotations from docs/contract.md section 14 verbatim, then `Handle` for each. `tools_skills.go` sorts after `defs.go`, so the two tools follow the 18 contract tools.
2. Declare an unexported seam `var newSkillsClient = func() *skills.Client { return skills.New(os.Getenv) }`. Handlers call it per call. Handlers never call `s.Credential`, never touch `s.Cache` and never use `s.API`.
3. `ajent_skills_search`: read `query` and `limit` (default 5; integers arrive as `float64`). Call `Search`. Return the `SearchResponse` as the value.
4. `ajent_skills_get`: read `id`, `version` and `offset` (default 0). Call `Get`. Convert the bytes to a rune slice. If `offset > total`, return a plain error (which becomes `client_error`). Return `{"id", "version", "format": "markdown_fragment", "content": runes[offset:min(offset+8000, total)], "offset", "next_offset": end or nil when end == total, "total_chars": total}`.
5. Map errors to `&ToolError{Payload: ...}` with the exact section 14 payloads: `skills.ErrUnavailable` gives `skills_unavailable`; `skills.ErrVerificationFailed` gives `skill_verification_failed`; `*skills.RejectedError` gives `skills_request_rejected` with `code` and `http_status`. `skills.ErrInvalidArgument` and anything else are returned as plain errors (`client_error`).
6. Tests (use `fakeskills`, set `AJENT_SKILLS_ORIGIN` with `t.Setenv`, and drive calls through the T3.2 dispatcher or `Serve` with a short transcript):
   - `TestSkillToolsListed`: `Tools()` ends with the two skill tools in order, with definitions equal to section 14 (compare decoded JSON).
   - `TestSkillsSearchCall`: the enveloped result contains the fake results.
   - `TestSkillsGetFragments`: content of 20,000 runes comes back in three fragments; concatenating them by following `next_offset` rebuilds the content, and the last `next_offset` is null.
   - `TestSkillsGetTampered`: `Tamper` gives isError with `"error":"skill_verification_failed"` and no content.
   - `TestSkillsUnavailable` (503) and `TestSkillsRejected` (404, `code` and `http_status` present).
   - `TestSkillsNoCredential`: the session has a `Resolve` that fails the test if called; both tools still succeed, and no fake request carries `Authorization`.

### Acceptance criteria

- All tests pass with `-race`, `GOOS=windows go vet` is clean and golangci-lint reports 0 issues.
- T3.2's `TestToolsMatchContract` still passes (the two tools are in its `goOnlyTools` list).
- Genuine-red check: make the get handler return the content without checking the error from `Get` (use the tampered bytes) and observe `TestSkillsGetTampered` fail; change one word in the `ajent_skills_search` description and observe `TestSkillToolsListed` fail. Restore and show both passing. Report all outputs.
