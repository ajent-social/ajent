## T1.3: Write the community health files

### Objective

A first-time contributor finds clear, short answers to these questions: how to build and test, how to sign off commits, how to report a vulnerability, how to file a useful bug, and what behavior is expected. GitHub shows the community profile as complete.

### Read first

- docs/adr/001-open-source-client-apache-2.md (DCO, trademark line)
- docs/adr/007-harness-integration-model.md (how a new harness writer is added)
- docs/design.md

### Scope

- `CONTRIBUTING.md`
- `CODE_OF_CONDUCT.md`
- `SECURITY.md`
- `.github/ISSUE_TEMPLATE/bug_report.yml`
- `.github/ISSUE_TEMPLATE/feature_request.yml`
- `.github/ISSUE_TEMPLATE/new_harness.yml`
- `.github/ISSUE_TEMPLATE/config.yml`
- `.github/PULL_REQUEST_TEMPLATE.md`
- `.github/CODEOWNERS`

### Out of scope

- README.md (T7.1), AGENTS.md (T1.6), docs/ pages (T7.2).
- Anything about the hosted service's implementation, infrastructure, pricing or roadmap.

### Steps

1. Style for all prose: Google developer documentation style. Use second person, active voice, present tense and sentence-case headings. Use ASCII only. Never use "please", "simply", "just", "easy", "obviously", "leverage", em dashes or emojis.
2. `CONTRIBUTING.md` headings, in order:
   - `# Contributing to ajent`: one paragraph thanking contributors and naming the three most useful contributions: harness writers, bug reports with `ajent doctor` output, and docs fixes.
   - `## Prerequisites`: Go 1.26 or later, and Git. Nothing else is needed. `golangci-lint` is optional locally, and CI runs it.
   - `## Build and test`: `make build`, `make test`, `make lint`, `make fmt`, each with a one-line description.
   - `## Sign your commits (DCO)`: explain the Developer Certificate of Origin in 3 sentences, link <https://developercertificate.org>, show `git commit -s -m "fix: ..."`, and explain how to fix a missing sign-off with `git commit --amend -s` or `git rebase --signoff main`.
   - `## Commit messages`: Conventional Commits (`feat:`, `fix:`, `docs:`, `chore:`, `refactor:`, `test:`, `ci:`). Note that release notes are generated from them.
   - `## Pull requests`: keep them small and focused, include tests, one logical change per commit, and CI must be green.
   - `## Adding support for a coding tool`: point to docs/adr/007-harness-integration-model.md. Name the file pattern `internal/integrations/<tool>.go` plus golden fixtures under `testdata/integrations/<tool>/`, and mention the `good first issue` label.
   - `## Security issues`: never file a public issue. See SECURITY.md.
   - `## License`: contributions are licensed under Apache-2.0.
3. `CODE_OF_CONDUCT.md`: the Contributor Covenant version 2.1 text from <https://www.contributor-covenant.org/version/2/1/code_of_conduct/code_of_conduct.md>. Convert any non-ASCII characters to ASCII equivalents. Replace the enforcement contact placeholder with: "reporting through GitHub's content reporting feature or by opening a private security advisory in this repository". Do not invent an email address.
4. `SECURITY.md` headings:
   - `# Security policy`
   - `## Reporting a vulnerability`: use GitHub private vulnerability reporting (Security tab, "Report a vulnerability"). Do not open public issues. Target an acknowledgement within 3 business days.
   - `## Scope`: this repository's client (CLI, MCP server, installers, integrations, updater). Issues in the hosted service at <https://ajent.social> can be reported through the same channel.
   - `## Supported versions`: a table with a single row, "Latest release: supported". Note that older releases receive fixes only through upgrading.
   - `## Verifying releases`: a placeholder paragraph that says the release signing key fingerprint is published here when the first release is cut, plus the line `Release signing key (Ed25519): TO BE ADDED BY T5.3`. Link docs/adr/004-release-signing.md.
   - `## Key rotation`: two sentences describing the procedure from ADR 004.
5. `.github/ISSUE_TEMPLATE/bug_report.yml` (GitHub issue forms): name `Bug report`, labels `["bug"]`, and fields:
   - textarea `what-happened` (required)
   - textarea `expected` (required)
   - textarea `doctor` with the label "Output of `ajent doctor`" and the description "Remove anything you consider private. Tokens are never printed." (required)
   - input `version` with the label "Output of `ajent version`" (required)
   - dropdown `os` with options macOS, Linux, Windows
   - dropdown `install` with options install script, Homebrew, apt, dnf, Scoop, winget, go install, other
   - dropdown `tool` with options Claude Code, Codex, Cursor, Gemini CLI, Copilot CLI, VS Code, other, none
6. `feature_request.yml`: name `Feature request`, labels `["enhancement"]`, textareas `problem` (required), `proposal` (required) and `alternatives`.
7. `new_harness.yml`: name `Support a new coding tool`, labels `["harness", "good first issue"]`, inputs `tool-name` and `docs-url` (link to the tool's MCP configuration docs), and textarea `config-example` (render: json).
8. `config.yml`: `blank_issues_enabled: false`. The `contact_links` entries are "Questions and ideas" pointing to <https://github.com/ajent-social/ajent/discussions>, and "Security vulnerability" pointing to <https://github.com/ajent-social/ajent/security/advisories/new>.
9. `.github/PULL_REQUEST_TEMPLATE.md`: sections `## What and why`, `## How it was tested` (a checklist: `make test` passes, new tests added, tested on OS: ...), and `## Checklist` (commits signed off, Conventional Commit title, docs updated if user-facing).
10. `.github/CODEOWNERS`: a single line `* @ajent-social/maintainers`. Verify that the team exists with `gh api orgs/ajent-social/teams/maintainers`. If it returns 404, use `* @dndungu` instead and note this in the PR body.
11. Validate the YAML files with `python3 -c "import sys,yaml; [yaml.safe_load(open(f)) for f in sys.argv[1:]]" .github/ISSUE_TEMPLATE/*.yml`. If PyYAML is missing, use `ruby -ryaml -e 'ARGV.each{|f| YAML.load_file(f)}'`.

### Acceptance criteria

- All listed files exist and the YAML files parse.
- `LC_ALL=C grep -n '[^ -~]' CONTRIBUTING.md CODE_OF_CONDUCT.md SECURITY.md .github/ISSUE_TEMPLATE/* .github/PULL_REQUEST_TEMPLATE.md` prints nothing. Tabs are allowed only in code blocks.
- No file mentions pricing, internal hostnames, internal project names, personal home paths or unreleased features.
- `grep -riE "please|simply|just |easy|obviously|leverage" CONTRIBUTING.md SECURITY.md` prints nothing.

### Verification

```bash
ls CONTRIBUTING.md CODE_OF_CONDUCT.md SECURITY.md .github/ISSUE_TEMPLATE/*.yml .github/PULL_REQUEST_TEMPLATE.md .github/CODEOWNERS
LC_ALL=C grep -n '[^ -~ ]' CONTRIBUTING.md CODE_OF_CONDUCT.md SECURITY.md || echo ascii-ok
grep -riE "please|simply|just |easy|obviously|leverage" CONTRIBUTING.md SECURITY.md || echo style-ok
```
