## T4.4: Write the Claude Code integration and plugin marketplace registration

### Objective

When the `claude` CLI is installed, `ajent integrations sync` registers the Ajent MCP server at user scope through the Claude Code CLI, pointing at the stable ajent binary. It also registers this repository as a Claude Code plugin marketplace. Reruns change nothing. An outdated ajent-owned or Python-era entry is replaced. A foreign `ajent` entry is left alone.

Decision (orchestrator, from the T2.1 contract freeze): Go writes the harness `env` block only when the config directory or credential file is non-default, while the Python client always wrote both variables (docs/contract.md section 9). Any existing `ajent` entry whose command runs `ajent mcp` or `client.py mcp` counts as ajent-owned (`Owned` in T4.17) and is replaced, so migration, post-upgrade sync and uninstall work on Python-era entries. This intentionally differs from the reference, which left any differing existing entry unchanged and, for Claude Code and Codex, kept any registration that `mcp get ajent` found. Entries that are not owned are still never modified.

- `testdata/integrations/claude/` (create fixtures: `claude-json-absent/`, `claude-json-owned-old/.claude.json`, `claude-json-foreign/.claude.json`, `claude-json-current/.claude.json`)

### Out of scope

- Editing `~/.claude.json` directly. All writes go through the `claude` CLI. The file is read only to inspect the current entry.
- Installing or enabling the plugin itself. Only the marketplace is registered. The user enables the plugin.

### Steps

1. `type claudeWriter struct{}` registered in `init()` with `Register(claudeWriter{})`. `Target()` returns `Target{Name: "claude", Profile: "claude-code"}`.
2. `Detect(p)` returns `true` when `LookPath("claude")` succeeds.
3. `Paths(p)` returns `[filepath.Join(p.Home, ".claude.json"), filepath.Join(p.Home, ".claude", "settings.json")]`. These are backed up by Sync because the CLI edits them.
4. The desired entry is `want := Entry(p, "claude-code")` plus `want["type"] = "stdio"`.
5. `current(p) (map[string]any, bool)`: read `<Home>/.claude.json`. On read or parse error, return `nil, false`. Return `mcpServers.ajent` as a map when present. Before comparing, delete a `"type"` key equal to `"stdio"` from both sides, and treat a missing `env` and an empty `env` object as equal.
6. `Apply(ctx, p)`:
   1. `existing, ok := current(p)`.
   2. If `ok && SameEntry(norm(existing), norm(want))`, set status `unchanged`.
   3. If `ok && !Owned(existing)`, return `Result{Name: "claude", Status: "incomplete", Detail: "an existing ajent entry with other settings was preserved"}, nil`.
   4. If `ok && Owned(existing)`: `Run(ctx, "claude", "mcp", "remove", "--scope", "user", "ajent")`. On error, return status `incomplete` with detail `setup incomplete; existing settings preserved, see <ConfigDir>/mcp-example.json`.
   5. When not unchanged: `b, _ := json.Marshal(want)` and `Run(ctx, "claude", "mcp", "add-json", "--scope", "user", "ajent", string(b))`. On error, return the same incomplete result. Otherwise set status `configured`. Never include the Run output in any Result or error.
   6. Marketplace: `out, err := Run(ctx, "claude", "plugin", "marketplace", "list")`. If `err == nil` and no line of `out` contains the word `ajent`, then `Run(ctx, "claude", "plugin", "marketplace", "add", "ajent-social/ajent")`. If either call fails, append `; plugin marketplace not registered` to Detail. On success append `; enable the plugin with: claude plugin install ajent@ajent`. The marketplace step never changes Status.
7. `Remove(ctx, p)`: if `current` shows an owned entry, `Run(..., "claude", "mcp", "remove", "--scope", "user", "ajent")` gives status `removed`. A foreign entry gives status `unchanged` with detail `foreign ajent entry preserved`. With no entry, status is `unchanged`. Then best-effort `Run(ctx, "claude", "plugin", "marketplace", "remove", "ajent")`, ignoring errors.
8. Tests in `claude_test.go` replace `Run` and `LookPath` with fakes (restore with `t.Cleanup`). The fake Run records the argv and emulates the CLI by editing `<Home>/.claude.json` for `mcp add-json` and `mcp remove`, and by keeping an in-memory marketplace list. Use `p := Params{Home: t.TempDir(), Binary: "/opt/ajent/bin/ajent", ConfigDir: <home>/.aj, GOOS: runtime.GOOS, Getenv: func(string) string { return "" }}`.
   - `TestClaudeDetect`: LookPath error gives false.
   - `TestClaudeAddWhenAbsent`: the recorded argv equals `claude mcp add-json --scope user ajent {"args":["mcp","--profile","claude-code","--project-profile"],"command":"/opt/ajent/bin/ajent","type":"stdio"}` (json.Marshal sorts map keys). Status is `configured`. Marketplace add is called with `ajent-social/ajent`.
   - `TestClaudeUnchangedSecondRun`: a second Apply records no `add-json` and no `remove`, and gives status `unchanged`.
   - `TestClaudeReplacesPythonEntry`: fixture `claude-json-owned-old` has `mcpServers.ajent = {"command":"/usr/bin/python3","args":["/h/.aj/client.py","mcp","--profile","claude-code","--project-profile"],"env":{"AJENT_CONFIG_DIR":"/h/.aj"}}`. The calls are `remove` then `add-json`.
   - `TestClaudeForeignPreserved`: fixture with `command: "npx"`. No mutating calls. Status `incomplete`.
   - `TestClaudeCLIFailure`: the fake Run fails `add-json`. Status `incomplete`, and Detail contains `mcp-example.json` but not the fake output text `SECRET-OUTPUT`.
   - `TestClaudeEnvForCustomConfigDir`: `ConfigDir = /x/custom`. The JSON contains `"env":{"AJENT_CONFIG_DIR":"/x/custom"}`.
   - `TestClaudeRemoveOwnedOnly`.

### Acceptance criteria

- All tests pass with `-race` on all three OSes.
- Genuine-red: skip the `Owned` check (always replace), then observe `TestClaudeForeignPreserved` fail. Restore and report both outputs.
- Genuine-red: put the Run output into Detail, then observe `TestClaudeCLIFailure` fail. Restore.
