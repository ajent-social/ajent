## T5.1: Configure release-please

### Objective

On every push to `main`, release-please opens or updates a release PR computed from Conventional Commits. Starting from the seeded version `0.6.0`, the first `feat:` commit proposes `0.7.0` and a `CHANGELOG.md` entry. Merging the release PR creates the `v0.7.0` tag and GitHub release, and exposes `release_created` and `tag_name` outputs. T5.11 later adds the GoReleaser job to the same workflow file.

### Read first

- docs/adr/002-go-stdlib-single-binary.md (version line continues at 0.7.0)
- docs/adr/003-distribution-channels.md
- <https://github.com/googleapis/release-please-action> (README, "Configuration" and outputs)

### Scope

Create only:

- `release-please-config.json`
- `.release-please-manifest.json`
- `.github/workflows/release.yml`

### Out of scope

- The GoReleaser job, signing, dispatches (T5.11). Leave a clearly marked placeholder comment for T5.11 at the end of `release.yml`.
- `CHANGELOG.md`, which release-please creates in its first PR. Do not create it by hand.
- `.github/release.yml` (T7.7).

### Steps

1. Create `release-please-config.json` with exactly:

   ```json
   {
     "$schema": "https://raw.githubusercontent.com/googleapis/release-please/main/schemas/config.json",
     "include-component-in-tag": false,
     "include-v-in-tag": true,
     "packages": {
       ".": {
         "release-type": "go",
         "package-name": "ajent",
         "changelog-path": "CHANGELOG.md",
         "bump-minor-pre-major": true,
         "bump-patch-for-minor-pre-major": false,
         "draft": false,
         "prerelease": false,
         "extra-files": [
           {"type": "json", "path": "plugins/ajent/.claude-plugin/plugin.json", "jsonpath": "$.version"},
           {"type": "json", "path": "plugins/ajent/.codex-plugin/plugin.json", "jsonpath": "$.version"},
           {"type": "json", "path": ".claude-plugin/marketplace.json", "jsonpath": "$.plugins[0].version"}
         ]
       }
     }
   }
   ```

   The three `extra-files` are the plugin and marketplace manifests created by T4.1. release-please rewrites their `version` fields in each release PR, which keeps T4.1's `TestVersionsAgree` green. They may not exist yet when this task lands. T4.1 lands before the first release PR is merged; until then a release-please warning about a missing extra file is expected and harmless. Do not create the files in this task.
2. Create `.release-please-manifest.json` with exactly `{".": "0.6.0"}` plus a trailing newline. From `0.6.0`, a `feat:` commit bumps to `0.7.0` and a `fix:` commit bumps to `0.6.1`. Explain this in the PR description, because the first release must be `0.7.0`: the first release PR must include at least one `feat:` commit since the seed.
3. Look up the current commit SHA of the release-please action's latest v4 release: `gh api repos/googleapis/release-please-action/releases/latest -q .tag_name`, then `gh api repos/googleapis/release-please-action/git/ref/tags/<tag> -q .object.sha`. If the object type is `tag`, dereference it with `gh api repos/googleapis/release-please-action/git/tags/<sha> -q .object.sha`.
4. Create `.github/workflows/release.yml` (SPDX header as a YAML comment on line 1: `# SPDX-License-Identifier: Apache-2.0`):

   ```yaml
   name: release
   on:
     push:
       branches: [main]
   permissions:
     contents: read
   concurrency:
     group: release
     cancel-in-progress: false
   jobs:
     release-please:
       runs-on: ubuntu-latest
       permissions:
         contents: write
         pull-requests: write
       outputs:
         release_created: ${{ steps.rp.outputs.release_created }}
         tag_name: ${{ steps.rp.outputs.tag_name }}
         version: ${{ steps.rp.outputs.version }}
       steps:
         - id: rp
           uses: googleapis/release-please-action@<SHA> # <tag>
           with:
             config-file: release-please-config.json
             manifest-file: .release-please-manifest.json
     # T5.11 adds the `goreleaser` job below this line. It runs only when
     # needs.release-please.outputs.release_created == 'true'.
   ```

   Tags created with `GITHUB_TOKEN` do not trigger other workflows, so the publishing job must live in this same workflow. That is why T5.11 extends this file instead of listening for tag pushes.
5. Validate the JSON files with `python3 -m json.tool` and the workflow with `actionlint` (run `go run github.com/rhysd/actionlint/cmd/actionlint@latest .github/workflows/release.yml`).

### Acceptance criteria

- `python3 -m json.tool release-please-config.json` and `python3 -m json.tool .release-please-manifest.json` succeed.
- `actionlint` reports no errors for `.github/workflows/release.yml`.
- After merge, a push of a `feat:` commit to `main` produces a release PR titled `chore(main): release 0.7.0` whose diff adds `CHANGELOG.md` and sets `.release-please-manifest.json` to `0.7.0`. Record the PR URL in your report. Do not merge that PR as part of this task.
- Genuine-red: temporarily change the manifest to `{".": "0.7.0"}` on a scratch branch and run `npx release-please release-pr --dry-run --repo-url=ajent-social/ajent --token=$(gh auth token) --target-branch=<scratch branch>`. The proposed version is `0.8.0` instead of `0.7.0`. Restore the manifest and report both outputs.

### Verification

- `python3 -m json.tool release-please-config.json >/dev/null && python3 -m json.tool .release-please-manifest.json >/dev/null`
- `go run github.com/rhysd/actionlint/cmd/actionlint@latest .github/workflows/release.yml`
- `gh pr list --repo ajent-social/ajent --search "release 0.7.0" --state open` (after merge)
