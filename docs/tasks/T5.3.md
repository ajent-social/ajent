## T5.3: Sign release checksums with Ed25519 and verify them in the client

### Split (2026-09-24)

This task is split so the verification code does not wait on the release key. **T5.3** does every step except the key-specific parts, and leaves `releaseKeys` empty: `var releaseKeys = []string{}` with the comment `// Filled by T5.3b with the T5.0 release key.` With no key, `PublicKeys` holds only a valid `extraKeyB64`, so official builds fail closed. `TestLoadKeysEmbedded` must pass with zero entries. T5.3 skips step 9 and the key parts of step 11 (the fingerprint and the "Release signing key" section). It still writes the `signs` block (step 10) and runs the step-12 check with a throwaway key. **T5.3b** (after T5.0) adds the real key to `releaseKeys` and does step 9 and step 11. It then reruns step 12 without `extraKeyB64`, signing with the real `RELEASE_ED25519_KEY` inside the protected release environment, or with a key the maintainer provides for a rehearsal. The "stop and report blocked" rule in step 4 applies only to T5.3b.

### Objective

Every release publishes `checksums.txt.sig`, an Ed25519 signature over the exact bytes of `checksums.txt`. The `ajent` binary carries the trusted public keys and verifies checksums and signatures with the standard library only (`update.VerifyChecksums`, `update.VerifyFile`). A hidden `ajent verify-release` command exposes the check. Changing one byte of `checksums.txt` or of the signature makes verification fail.

### Steps

1. Signature format (the fixed contract, also used by T5.9, T6.2 and T6.3):
   - The signed message is the exact byte content of `checksums.txt`.
   - `checksums.txt.sig` is the standard base64 encoding (with padding) of the 64-byte Ed25519 signature, followed by a single `\n`. Readers must trim surrounding ASCII whitespace before decoding.
   - `RELEASE_ED25519_KEY` is standard base64 of the 32-byte Ed25519 seed. For robustness, the signer also accepts base64 of the 64-byte private key.
   - Public keys are embedded as standard base64 of the 32-byte raw key.
2. Create `internal/tools/signchecksums/main.go` (package `main`, SPDX header, stdlib only). Flags:
   - `-in <path>` and `-out <path>`: read `-in`, sign with the key from env `RELEASE_ED25519_KEY`, and write the signature file (mode 0644).
   - `-keygen <prefix>`: generate a new key pair with `ed25519.GenerateKey(rand.Reader)`, write `<prefix>.seed` (base64 seed plus newline, mode 0600), `<prefix>.pub` (base64 public key plus newline, mode 0644) and `<prefix>.pem` (PKIX `PUBLIC KEY` PEM from `x509.MarshalPKIXPublicKey`, mode 0644), then exit. This mode is for tests and rehearsals only (T5.9, T5.13, T6.8 use the `.pem` and `.pub` files).
   - Exit codes: 0 on success. 1 when the key is missing, malformed or the wrong length, with a message on stderr that never includes key material. 2 on bad flags.
3. Create `internal/tools/signchecksums/main_test.go`. Put the logic in `func run(args []string, getenv func(string) string, stderr io.Writer) int` so tests call it directly. Tests:
   - `TestSignRoundTrip`: keygen into `t.TempDir()`, sign a file, verify the signature with `ed25519.Verify`, and assert the `.pem` parses with `x509.ParsePKIXPublicKey` to the same key.
   - `TestMissingKey`: exit 1, and stderr contains `RELEASE_ED25519_KEY`.
   - `TestBadKeyLength`: a base64 value of 10 bytes gives exit 1.
   - `TestAccepts64ByteKey`: sign with a 64-byte private key and verify.
4. Create `internal/update/keys.go`:

   ```go
   // releaseKeys lists trusted Ed25519 release public keys (standard base64 of 32 raw bytes).
   // Rotation: add the new key here and ship a release, then remove the old key in a later release.
   var releaseKeys = []string{
       "<RAW BASE64 PUBLIC KEY FROM T5.0>",
   }

   // extraKeyB64 is set only with -ldflags "-X github.com/ajent-social/ajent/internal/update.extraKeyB64=..."
   // for tests and release rehearsals. Official release builds never set it.
   var extraKeyB64 string

   // PublicKeys are the trusted Ed25519 release keys.
   var PublicKeys = loadKeys()
   ```

   `loadKeys` decodes each entry and panics when an entry is not exactly 32 bytes. That is a build-time programming error, and a unit test covers it. It then appends the key decoded from `extraKeyB64` when that is non-empty and valid, and ignores it otherwise.
   If the T5.0 hand-off key is not available yet, stop and report the task as blocked on T5.0. Never commit a placeholder or a key you generated yourself.
5. Create `internal/update/verify.go`:
   - `func VerifyChecksums(checksums, sig []byte, keys []ed25519.PublicKey) error`: trim whitespace from `sig`, base64-decode it, require 64 bytes, and return nil if any key verifies. Otherwise return `ErrBadSignature` (declare `var ErrBadSignature = errors.New("update: release signature does not verify")`). With an empty key list, return `ErrBadSignature`.
   - `func VerifyFile(checksums []byte, name string, data []byte) error`: parse lines of the form `<64 hex>  <name>` (two spaces, as GoReleaser writes them; also accept one space or `*` binary markers). Find `name` exactly, and compare `sha256(data)` in lowercase hex with a constant-time comparison. Return `ErrChecksumMismatch` when the hash differs and `ErrNotListed` when the name is absent (declare both sentinels).
6. Create `internal/update/verify_test.go`. Tests generate keys at test time. Cases:
   - `TestVerifyChecksumsValid`
   - `TestVerifyChecksumsTamperedMessage` (flip one byte of checksums)
   - `TestVerifyChecksumsTamperedSignature` (flip one byte of the decoded signature)
   - `TestVerifyChecksumsSecondKeyOfRotation` (signed by the 2nd key of 2)
   - `TestVerifyChecksumsNoKeys`
   - `TestVerifyChecksumsTrailingWhitespace`
   - `TestVerifyFileMatch`, `TestVerifyFileMismatch`, `TestVerifyFileNotListed`, `TestVerifyFileSimilarNames` (`ajent_1.0.0_linux_amd64.tar.gz` versus `ajent_1.0.0_linux_amd64.tar.gz.sbom.json`)
   - `TestLoadKeysEmbedded`: every entry in `releaseKeys` decodes to 32 bytes
7. Create `cmd/ajent/cmd_verify_release.go`. In `init()`, call `cli.Register(cli.Command{Name: "verify-release", Hidden: true, Summary: "Verify a release checksums file and its signature", Run: runVerifyRelease})`. Flags: `--checksums <path>` (required), `--sig <path>` (required), `--file <path>` (optional; also check this file's hash against the checksums, using its base name). On success print `ok` to stdout and return nil. On failure return an error whose message is `release verification failed: <reason>`, which gives exit code 1 through `cli.Main`. Missing required flags return `cli.ErrUsage`.
8. Create `cmd/ajent/cmd_verify_release_test.go`. Call `cli.Main` with an `Env` whose `Stdout` and `Stderr` are buffers. Temporarily append a test key to `update.PublicKeys` (restore with `t.Cleanup`). Cases: valid returns 0 and prints `ok`, a tampered checksums file returns 1, a missing `--sig` returns 2.
9. Write `packaging/ajent-release.pub.pem` with the PEM from the T5.0 hand-off, byte for byte.
10. Fill the `signs` marker block in `.goreleaser.yaml`:

    ```yaml
    # ---- BEGIN signs (T5.3) ----
    signs:
      - id: ed25519
        artifacts: checksum
        signature: "${artifact}.sig"
        cmd: go
        args: ["run", "./internal/tools/signchecksums", "-in", "${artifact}", "-out", "${signature}"]
    # ---- END signs (T5.3) ----
    ```

    Do not add an `env:` list. GoReleaser templates `signs[].env` against the list's own earlier entries, not the process environment, so `{{ .Env.RELEASE_ED25519_KEY }}` fails there. The sign command already inherits `RELEASE_ED25519_KEY` from the release job's environment.

11. Update `SECURITY.md`. Replace the fingerprint placeholder with the SHA-256 fingerprint from T5.0. Append a section `## Release signing key` that gives the raw base64 public key, the PEM path `packaging/ajent-release.pub.pem`, the URL `https://pkg.ajent.social/ajent-release.pub`, the verification commands (`ajent verify-release --checksums checksums.txt --sig checksums.txt.sig --file <archive>` and the OpenSSL 3 equivalent: `base64 -d checksums.txt.sig > sig.bin && openssl pkeyutl -verify -pubin -inkey ajent-release.pub.pem -rawin -in checksums.txt -sigfile sig.bin`), and the rotation procedure from ADR 004.
12. Local end-to-end check: generate a throwaway key with `go run ./internal/tools/signchecksums -keygen $TMP/k`, then export `RELEASE_ED25519_KEY=$(cat $TMP/k.seed)`. Build with `go build -ldflags "-X github.com/ajent-social/ajent/internal/update.extraKeyB64=$(cat $TMP/k.pub)" -o $TMP/ajent ./cmd/ajent`. Run `goreleaser release --snapshot --clean --skip=notarize,publish` (signing enabled), then `$TMP/ajent verify-release --checksums dist/checksums.txt --sig dist/checksums.txt.sig --file dist/<linux_amd64 archive>`.

### Acceptance criteria

- `go test ./internal/update/... ./internal/tools/signchecksums/... ./cmd/ajent/... -race -count=1` passes on ubuntu, macos and windows CI.
- The local end-to-end check in step 12 prints `ok`, and `dist/checksums.txt.sig` exists.
- After `printf 'x' >> dist/checksums.txt`, the same command exits 1 with `release verification failed`.
- The OpenSSL 3 command from step 11 prints `Signature Verified Successfully` for the step-12 artifacts when run with the throwaway PEM (derive the PEM from the seed with the Go helper, or with OpenSSL from a generated PEM).
- Genuine-red: change `VerifyChecksums` to return nil unconditionally, run `go test ./internal/update -run TestVerifyChecksumsTampered -count=1`, and observe both tampered tests fail. Restore the code, rerun, and report both outputs.
- `gofmt -l .` is empty, and `go vet ./...` and `golangci-lint run ./internal/update/... ./internal/tools/... ./cmd/...` pass.
