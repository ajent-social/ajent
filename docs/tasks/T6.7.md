## T6.7: Document automatic upgrades for package managers

### Objective

`docs/upgrading.md` tells every user how ajent stays current on their channel. Script installs update automatically and can opt out. Each package manager gets exact, tested commands for its own automatic upgrades: Homebrew autoupdate, APT unattended-upgrades for the `pkg.ajent.social` origin, dnf-automatic, and scheduled Scoop and winget upgrades. Pinning, rollback and verification are also covered.

### Read first

- docs/adr/005-upgrade-strategy.md, docs/adr/003-distribution-channels.md
- docs/tasks/T5.7.md step 3.7 (APT `Origin: ajent`, `Label: ajent`, suite `stable`)
- docs/tasks/T6.1.md step 3 (`UpgradeCommand` strings; the doc must use the same commands)
- docs/tasks/T6.3.md (`ajent update` flags)

### Scope

Create only `docs/upgrading.md`.

### Out of scope

- README changes (T7.1 links to this page). Code changes.

### Steps

1. Style: Google developer documentation style, second person, present tense, sentence-case headings, ASCII only, no hype words, no pricing, and no internal names or hosts other than `ajent.social`, `pkg.ajent.social` and `github.com/ajent-social/...`.
2. Write these sections in this order:
   1. `# Upgrading ajent`: one paragraph on why staying current matters (new service capabilities need newer clients) and a table mapping install channel to upgrade command, using exactly the `UpgradeCommand` strings, plus `ajent update` for script installs.
   2. `## Script installs update automatically`: default on; checks at most once a day at session start; applies only signed stable releases; the log is at `~/.aj/update.log`. Opt out with `ajent update --auto off` or `AJENT_AUTO_UPDATE=0`. Updates are always off when `CI` is set. Check status with `ajent update --auto status`, update now with `ajent update`, and pin with `ajent update --version 0.7.0`.
   3. `## Homebrew`: `brew upgrade ajent`. Automatic: `brew tap domt4/autoupdate` then `brew autoupdate start 86400 --upgrade`. Note that this third-party tap upgrades every package on the machine.
   4. `## Debian and Ubuntu (APT)`: `sudo apt update && sudo apt install --only-upgrade ajent`. Automatic: `sudo apt install unattended-upgrades`, then create `/etc/apt/apt.conf.d/51ajent-unattended-upgrades` containing exactly:

      ```text
      Unattended-Upgrade::Origins-Pattern {
              "origin=ajent,label=ajent,a=stable";
      };
      ```

      Then run `sudo unattended-upgrade --dry-run --debug 2>&1 | grep -i ajent` to confirm the origin is allowed.
   5. `## Fedora and RHEL (DNF)`: `sudo dnf upgrade ajent`. Automatic, DNF 4: `sudo dnf install dnf-automatic`, set `apply_updates = yes` in `/etc/dnf/automatic.conf`, then `sudo systemctl enable --now dnf-automatic.timer`. DNF 5 (Fedora 41 and later): `sudo dnf install dnf5-plugin-automatic`, then `sudo systemctl enable --now dnf5-automatic.timer` with `apply_updates = yes` in `/etc/dnf/automatic.conf`. Add a note to check `man dnf-automatic` for the installed version.
   6. `## Windows (winget)`: `winget upgrade --id AjentSocial.Ajent --exact`. Automatic: a daily scheduled task, `schtasks /Create /SC DAILY /ST 09:00 /TN "ajent upgrade" /TR "winget upgrade --id AjentSocial.Ajent --exact --silent --accept-package-agreements --accept-source-agreements"`. Remove it with `schtasks /Delete /TN "ajent upgrade" /F`.
   7. `## Windows (Scoop)`: `scoop update ajent`. Automatic: `schtasks /Create /SC DAILY /ST 09:00 /TN "ajent scoop update" /TR "powershell -NoProfile -Command scoop update ajent"`.
   8. `## What happens after an upgrade`: on the next agent session start, ajent refreshes its coding-tool integrations once so they launch the new binary. It keeps a backup, restorable with `ajent rollback <id>`. Credentials are never touched.
   9. `## Verify what you installed`: `ajent version`, and a link to `verifying-releases.md` (T7.2).
   10. `## Roll back`: script installs use `ajent update --version <previous>`. Homebrew and package managers follow their own rollback instructions: for APT, `sudo apt install ajent=<version>`; for DNF, `sudo dnf downgrade ajent`.
3. Check every command yourself where possible:
   - Run the APT snippet's `apt.conf` syntax check in a `debian:stable` container: install `unattended-upgrades` and run `unattended-upgrade --dry-run --debug` with the file present. The grep may find nothing before the repository has packages, but the command must not report a config parse error.
   - Run `schtasks` syntax on a Windows runner only if available. Otherwise mark it `not executed` in your report.
4. Run a link check with `npx markdown-link-check docs/upgrading.md`, or `lychee` if T7.6 has landed.

### Acceptance criteria

- `docs/upgrading.md` exists with the ten sections in order, and every command string matches T6.1's `UpgradeCommand` and T6.3's flags.
- The APT config snippet parses in the container (report the output).
- `grep -nP '[^\x00-\x7F]' docs/upgrading.md` prints nothing.
- The link check passes, apart from links to pages that do not exist yet (`verifying-releases.md`), which are listed in the report.
