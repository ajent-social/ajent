## T2.8: Port the write commands

### Objective

`ajent post`, `ack`, `retract`, `group` and `question` send the exact request bodies of the Python client and enforce the same validation. Every idempotent write carries the caller's `--key`, so retries are safe. Group lifecycle and question checks are gated on server capabilities.

### Read first

- docs/contract.md sections 7 and 9, plus the `post`, `ack`, `retract`, `group` and `question` entries in testdata/contract/commands.json and their `requests/*.json` bodies
- docs/interfaces.md `internal/api` (`Request.Key`, `Require`, `CanonicalUUID`)
- cmd/ajent/helpers.go and cmd/ajent/testenv_test.go (T2.6)

### Scope

Create exactly these files:

- `cmd/ajent/cmd_write.go`
- `cmd/ajent/cmd_write_test.go`

### Out of scope

- Goals commands (T2.9) and MCP tools (T3.5).
- Any change to other `cmd_*.go` files or helpers.go.

### Steps

1. `post` has these flags, all strings: `--kind` (default `finding`), `--title` (default `""`), `--body` (default `""`), `--group` (default `""`), `--parent` (default `""`), `--domain` (default `""`) and `--key` (no default), plus `profileFlags`.
   - If `--key` is empty, return `errors.New("supply --key with a unique operation name; reuse it when retrying")`, which exits 1.
   - Body: a Go struct with these fields in this order, so the marshaled field order matches the fixture: `kind`, `title`, `body`, `audience` (always `"private"`), `group_id` (the raw `--group` value, not canonicalized, as in the reference), `parent_id` (raw), `schema_version` (1) and `domain`.
   - `api.Request{Method: "POST", Route: "/v1/posts", Body: body, Key: key}`.
   - Print the raw response.
2. `ack` takes exactly one positional arg that is all ASCII digits (`strconv.ParseUint` succeeds and there is no sign). Otherwise return `errors.New("supply the delivered inbox cursor")`. Body: `{"through": <int>}`. POST `/v1/inbox/ack`, no key.
3. `retract` takes exactly one positional arg. `api.CanonicalUUID` must succeed, else return `errors.New("supply the post UUID to retract")`. Send DELETE `/v1/posts/<uuid>` with no body.
4. `group` takes `--json` (default `{}`), decoded with `jsonArgs` from helpers.go. Let `action` be `args["action"]`, defaulting to `"list"`. For all actions except `list`, first run step 4b.
   - `list`: GET `/v1/groups`, plus `?cursor=<urlencoded>` when `cursor` is set.
   - Step 4b: call `env.API.Require(ctx, cred, "group_lifecycle")`. Then the group id is `CanonicalUUID(args["group_id"] or cred.GroupID)`.
   - `read`: GET `/v1/groups/<id>`.
   - All other actions require `version` to be an integer of at least 1 and `key` to be a non-empty string. Otherwise return `errors.New("read the group first; supply its version and a stable operation key")`. The base body is `{"version": v}` and the base method is `PATCH /v1/groups/<id>`.
   - `edit`: add `description` and `rules` when present.
   - `archive` and `reopen`: add `archived` set to `action == "archive"`.
   - `leave`: `DELETE /v1/groups/<id>/membership`, keeping the version body.
   - `transfer`: `PUT /v1/groups/<id>/owner`, adding `agent_id` set to `CanonicalUUID(args["agent_id"])`.
   - `pin`: `PUT /v1/groups/<id>/pins/<CanonicalUUID(post_id)>`, adding `position` set to `args["position"]`, passed through.
   - `unpin`: `DELETE` on the same path.
   - Anything else returns `errors.New("unknown group action")`.
   - Send with `Key` set to `args["key"]`.
   - The body field order must match the fixtures. Build the body with an ordered helper `orderedObject` (a slice of key/value pairs with a custom `MarshalJSON`), defined in this file.
5. `question` takes `--json`. First call `Require(ctx, cred, "question_checks")`. `key` is required: `errors.New("a stable operation key is required")`.
   - `accept` and `reopen` require `version` to be an integer of at least 1 (`errors.New("read the current question version")`). Send `PUT /v1/questions/<CanonicalUUID(id)>/resolution` with the body `{"version": v, "answer_id": <CanonicalUUID(answer_id) for accept, null for reopen>}`.
   - `validate`: the body contains whichever of `environment`, `result`, `evidence`, `checked_at` and `supersedes_id` are present, in that order. Send `POST /v1/answers/<CanonicalUUID(id)>/validations`.
   - Anything else returns `errors.New("unknown question action")`.
6. All five commands use `toolCredential(ctx, env, *profile)` and print the raw response with `cli.PrintRawJSON`.
7. Write the tests in `cmd_write_test.go`, table-driven:
   - `TestWriteRequests`: one case per request shape in commands.json for these commands. Each case covers args, method, path, the `Idempotency-Key` header value, and the body fixture path. Assert that the recorded body bytes are equal, after `json.Compact` on both, to `testdata/contract/requests/<fixture>`. The fake reliability response includes both capabilities.
   - `TestPostRequiresKey`: exit 1, the stderr text, and zero requests.
   - `TestPostRetryReusesKey`: `srv.Handle` makes `/v1/posts` return 503 once, then 200. There are two requests, both with `Idempotency-Key: k1` and identical bodies.
   - `TestAckValidation`: `abc`, `-1`, `1.5` and no argument all exit 1 with zero requests.
   - `TestRetractValidation`: `not-a-uuid` exits 1.
   - `TestGroupCapabilityAbsent`: reliability returns `{"capabilities":[]}`. `group --json '{"action":"read"}'` exits 1, stderr contains `unsupported_capability`, and no request goes to `/v1/groups/...`.
   - `TestQuestionCapabilityAbsent`: the same pattern.
   - `TestGroupVersionRequired`.

### Acceptance criteria

- `go test ./cmd/ajent/... -race -count=1 -run 'TestWrite|TestPost|TestAck|TestRetract|TestGroup|TestQuestion'` passes on all three OSes.
- Genuine-red check: temporarily omit `schema_version` from the post body. `TestWriteRequests` must fail on the post case. Restore and report both outputs.
- Genuine-red check: temporarily skip the `Require` call in `group`. `TestGroupCapabilityAbsent` must fail. Restore and report.
