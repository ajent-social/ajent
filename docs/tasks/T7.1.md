## T7.1: Write the README

### Objective

A developer who lands on the repository understands the value within 10 seconds, can copy a one-line install for their OS, knows exactly what `ajent setup` will do to their machine, and can check every privacy claim. The README converts visitors into installs by being specific and honest, not by hype.

### Read first

- docs/plan.md, section 1 Context and Appendix A (tagline options, description, package description)
- docs/adr/003-distribution-channels.md (install commands per channel)
- docs/adr/005-upgrade-strategy.md, docs/adr/006-client-trust-boundaries.md, docs/adr/007-harness-integration-model.md
- docs/contract.md, command table (produced by T2.1)
- docs/tasks/T5.9.md, if present (install script env vars)

### Scope

- `README.md`

### Out of scope

- Other docs pages (T7.2). Link to their future paths even if they do not exist yet: `docs/install.md`, `docs/harnesses.md`, `docs/privacy.md`, `docs/verifying-releases.md`, `docs/upgrading.md`, `docs/troubleshooting.md`, `docs/commands.md`, `docs/mcp-tools.md`.
- The demo GIF (T7.5). Reference `docs/assets/demo.gif` inside an HTML comment until T7.5 lands. T7.5 uncomments it.
- Never include: pricing or "free" claims, user counts, comparisons naming competitors, roadmap promises or dates, internal hostnames, internal project names, personal paths, or the service's implementation details.

### Steps

1. Style: Google developer documentation style. Use second person, active voice, present tense and sentence-case headings. ASCII only, with no emojis and no em dashes. Never use: "please", "simply", "just", "easy", "effortless", "seamless", "powerful", "revolutionary", "leverage", "supercharge", "blazing". Every claim must be something the code does.
2. Write the README with exactly these sections, in order:
   - `# ajent`: then the chosen tagline from Appendix A as a single bold line. Use "Your agents keep solving the same problem. Let them share the answer." Follow it with the badge row: CI (`https://github.com/ajent-social/ajent-client/actions/workflows/ci.yml/badge.svg`), latest release (shields.io `github/v/release/ajent-social/ajent-client`), license (shields.io `github/license/ajent-social/ajent-client`), and Go Report Card (`https://goreportcard.com/badge/github.com/ajent-social/ajent-client`).
   - An intro paragraph of at most 3 sentences: ajent connects the coding agents you already use (Claude Code, Codex, Cursor, Gemini CLI, GitHub Copilot and VS Code) to a shared, private workspace of checked findings on <https://ajent.social>. When one agent solves a problem, the others can find the answer, check it and reuse it. This repository is the open-source client: the CLI, the MCP server and the installers.
   - `<!-- ![ajent demo](docs/assets/demo.gif) -->`
   - `## Why`: 3 bullets. Agents start every session from zero. Useful fixes stay in transcripts that no other agent reads. Copying notes between tools by hand does not scale. End with one sentence on how ajent helps: agents search before they work and share what they verified.
   - `## Install`: sub-headings `### macOS and Linux`, `### Windows`, `### Package managers`, then a note that every method installs the same signed binary.
     - macOS and Linux: `curl -fsSL https://ajent.social/install.sh | sh`
     - Windows (PowerShell): `irm https://ajent.social/install.ps1 | iex`
     - Package managers, as a table with columns Tool and Command:
       - Homebrew: `brew install ajent-social/tap/ajent`
       - Debian and Ubuntu: link to `docs/install.md#apt`, plus a two-line snippet of the deb822 source setup using `https://pkg.ajent.social`
       - Fedora and RHEL: link to `docs/install.md#dnf`
       - Scoop: `scoop bucket add ajent https://github.com/ajent-social/scoop-bucket` then `scoop install ajent`
       - winget: `winget install AjentSocial.Ajent`
       - Go: `go install github.com/ajent-social/ajent-client/cmd/ajent@latest`
     - Add a one-line note: "Until the hosted URLs switch over, use `https://pkg.ajent.social/install.sh` and `install.ps1`." Wrap it in an HTML comment so E8 can delete it.
   - `## Connect your agents`: run `ajent setup`. Then a numbered list, "What `ajent setup` does", that describes the steps honestly:
     1. Creates a private credential in `~/.aj` (Windows: `%USERPROFILE%\.aj`), readable only by you.
     2. Opens a browser link so you can approve this installation with your Ajent account, and shows a code to compare.
     3. Detects the coding tools you have installed and adds an `ajent` MCP server entry to each one, keeping your other settings.
     4. Saves a backup of every file it changes. `ajent rollback <id>` restores it.
     5. Uploads nothing from your projects.
   - `## Supported tools`: a table with columns Tool, How ajent connects and Config location. Rows: Claude Code (`claude mcp add-json` plus plugin), Codex (`codex mcp add` plus plugin), Cursor (`~/.cursor/mcp.json`), Gemini CLI (`~/.gemini/settings.json`), GitHub Copilot CLI (`~/.copilot/mcp-config.json`), VS Code (user `mcp.json`). Add a line: "Using another MCP client? Copy `~/.aj/mcp-example.json`." Link to docs/harnesses.md. Add: "Want another tool supported? Open a 'Support a new coding tool' issue."
   - `## Try it`: 4 example prompts to give an agent, in a code block:
     - `Search Ajent for findings about this error before you start.`
     - `Share what you just verified with my other agents.`
     - `Check my Ajent inbox.`
     - `Log me into Ajent.`
     Follow with the equivalent CLI commands: `ajent search "..."`, `ajent inbox` and `ajent login`.
   - `## Privacy and data`: short bullet claims, each ending with a link to docs/privacy.md or an ADR. Claims to include, from ADR 006:
     - Content leaves your machine only when an agent or you post it.
     - Project files, transcripts and credentials are never uploaded.
     - Credentials go only to the server they were issued by. Redirects are never followed.
     - Settings inside a repository cannot grant sharing access or change the server.
     - Posts expire after 30 days by default.
     - No telemetry. Product feedback stays on your machine until you turn it on with `ajent feedback set`.
     - Update checks send only the version, OS and architecture.
   - `## Verify a download`: 3 lines covering `checksums.txt` plus `checksums.txt.sig` (Ed25519), `gh attestation verify <file> --repo ajent-social/ajent-client`, and the key fingerprint in SECURITY.md. Link docs/verifying-releases.md.
   - `## Upgrade`: script installs update automatically once a day after verifying signatures, and you can opt out with `ajent update --auto off` or `AJENT_AUTO_UPDATE=0`. Package-manager installs upgrade through the manager (`brew upgrade ajent`, `sudo apt upgrade`, `scoop update ajent`, `winget upgrade AjentSocial.Ajent`). `ajent update --check` shows what is available. Link docs/upgrading.md.
   - `## Uninstall`: `ajent uninstall` removes ajent's entries from every tool and keeps your credential. `ajent uninstall --purge` also deletes it. Then remove the binary with your package manager, or delete it from `~/.local/bin`.
   - `## FAQ`: questions as `###` headings, each with a 1 to 3 sentence answer:
     - "Is the Ajent service open source?" No. This client is open source (Apache-2.0). The hosted service at ajent.social is not. You can read exactly what the client sends.
     - "What does it cost?" See <https://ajent.social>. Make no price or "free" claims.
     - "Does it work offline?" The CLI and MCP server need the service for search and sharing. Setup and rollback work offline.
     - "Can a repository I clone change what ajent shares?" No, per ADR 006.
     - "Where are my credentials?" In `~/.aj`, with owner-only permissions on macOS and Linux.
     - "How do I report a security issue?" See SECURITY.md.
   - `## Contributing`: 2 sentences plus links to CONTRIBUTING.md and good first issues (`https://github.com/ajent-social/ajent-client/labels/good%20first%20issue`).
   - `## License`: "Apache License 2.0. See LICENSE. The Ajent name and logo are trademarks and are not covered by the license."
3. Every command in the README must match docs/contract.md. If docs/contract.md does not list a command or flag used above (for example `ajent update --auto`), keep it only if its task row exists in docs/plans/, and mark it in the PR body as "documented ahead of implementation".
4. Keep the README under 250 lines.

### Acceptance criteria

- All sections from step 2 exist, in order. `grep -c '^## ' README.md` is at least 12.
- `LC_ALL=C grep -n '[^ -~]' README.md` prints nothing.
- `grep -niE 'please|simply|just |easy|effortless|seamless|powerful|revolutionary|leverage|supercharge|blazing|free tier|\$[0-9]' README.md` prints nothing.
- No hostnames other than `ajent.social`, `pkg.ajent.social`, `github.com`, `img.shields.io`, `goreportcard.com`, `developercertificate.org` and `modelcontextprotocol.io` appear: `grep -oE 'https?://[^/ )]+' README.md | sort -u`.
- The file is under 250 lines.
