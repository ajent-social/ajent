## T3.4: Persist the delivery cache

### Objective

The MCP delivery cache survives process restarts. Two sessions of the same profile, in sequence or concurrently, share which items were already delivered, so repeated content is not re-sent to the agent. The store is a small, locked, bounded JSON file with owner-only permissions. A corrupt or unwritable file never breaks the MCP server.

### Read first

- docs/interfaces.md, sections "internal/mcp" (Cache) and "internal/config" (WritePrivate, ReadJSON, Acquire).
- docs/adr/002-go-stdlib-single-binary.md (why SQLite was replaced).
- `internal/mcp/cache.go` as shipped by T3.2 (memory-only, with an unexported `persist` hook).

### Scope

Modify or create only:

- `internal/mcp/cache.go`
- `internal/mcp/cache_test.go`

### Out of scope

- Changing the exported Cache API or `Key`.
- Any other file in `internal/mcp` or elsewhere.

### Steps

1. File location: `<dir>/cache/<profile>.json`. Create the `cache` directory with `config.EnsurePrivateDir`. Lock file: `<dir>/cache/<profile>.lock`. Validate `profile` against `^[a-z0-9][a-z0-9-]{1,39}$`. If it is invalid, stay memory-only.
2. File format: `{"version":1,"entries":{"<hex key>":<unix seconds>}}`. Store only the hex keys, which are SHA-256 hashes. Never store post content, queries or credentials.
3. `OpenCache(dir, profile)`: attempt to load the file under `config.Acquire(lockPath, 1*time.Second)`. On any error (lock timeout, parse error, wrong version, symlink), log nothing, drop to memory-only for reads, and still attempt writes later. Keep the loaded entries in memory. Drop entries older than 30 days on load.
4. `Remember(keys...)`: update memory first, then persist. Acquire the lock for up to 1s. Re-read the file so concurrent writers merge rather than clobber. Add the keys with the current time, drop entries older than 30 days, keep the newest 20,000 by timestamp (ties broken by key, ascending), and write with `config.WriteJSON`. Any error leaves memory updated and returns silently.
5. `Seen(key)`: check memory only. `Close()`: release nothing persistent (there is no open handle between calls) and return nil.
6. Inject time for tests with an unexported package variable `cacheNow = time.Now`.
7. Write these tests:
   - `TestCachePersistsAcrossOpen`: open, remember, close. A second `OpenCache` on the same dir and profile sees the key.
   - `TestCacheExpiresAfter30Days`: remember at T0. Advance `cacheNow` by 31 days, and a fresh open does not see the key.
   - `TestCacheBoundedTo20000`.
   - `TestCacheConcurrentWritersMerge`: two caches on the same profile each remember distinct keys. A third open sees both.
   - `TestCacheCorruptFileDegrades`: write `{not json` to the file. Open, Seen and Remember do not panic, and after Remember the file is valid again.
   - `TestCacheFileModeUnix`: skip on windows. The file mode is 0600 and the dir mode is 0700.
   - `TestCacheSymlinkRefused`: skip on windows. With a symlinked cache file, the target is not modified.
   - `TestCacheInvalidProfileMemoryOnly`.

### Acceptance criteria

- All step 7 tests pass with `-race` on ubuntu, macos and windows. The unix-only tests skip on windows with `t.Skip("unix permissions")`.
- The cache file never contains anything but hex keys and integers.
- Genuine-red check: temporarily remove the re-read in `Remember`. Observe `TestCacheConcurrentWritersMerge` fail, then restore it. Temporarily remove the 30-day filter. Observe `TestCacheExpiresAfter30Days` fail, then restore it. Report both outputs.
