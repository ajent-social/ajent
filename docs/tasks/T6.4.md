## T6.4: Sync integrations after an upgrade

### Objective

After a new ajent version first runs (whether Homebrew, apt, Scoop or winget installed it, or the self-updater replaced it), every configured coding tool is re-synced exactly once. That rewrites any harness entry that points at an old or versioned binary path so it points at the stable path. The session-start hook starts a detached `ajent post-upgrade` process under a lock, and that process records `State.SeenVersion` when it finishes. Nothing is written to stdout in the hook or MCP paths.

- `cmd/ajent/hook_postupgrade_test.go`

### Out of scope

- Changes to `cmd_hook.go`, `internal/integrations` or `internal/update`. If an API named here is missing, stop and report BLOCKED with the missing identifier.
- Plugin file refresh. The Claude Code plugin comes from the repository marketplace, so the harness updates it, not ajent.

### Steps

1. In `hook_postupgrade.go` (package main), add `func needsPostUpgrade(configDir string) bool`. It returns true only when all of these hold:
   - `version.Version != "dev"` and it does not contain `SNAPSHOT`.
   - `filepath.Join(configDir, "integration-status.json")` exists, which means the user has set up integrations.
   - `update.LoadState(configDir)` returns a state whose `SeenVersion != version.Version`.
2. `init()` does two things:
   1. Appends to `sessionStartExtras` a func `(ctx, env)` that resolves `dir, err := env.Dir()`, returns on error, returns when `!needsPostUpgrade(dir)` or when `env.Getenv("AJENT_DETACHED") == "1"`, and otherwise calls `startDetached(exe, []string{"post-upgrade"}, filepath.Join(dir, "update.log"))` (the seam T6.3 declares in `cmd_update.go`), where `exe` comes from `os.Executable()`. Errors are ignored silently, because the hook never fails.
   2. Registers `cli.Command{Name: "post-upgrade", Hidden: true, Summary: "Re-sync coding-tool integrations after an upgrade", Run: runPostUpgrade}`.
3. `runPostUpgrade(ctx, env, args)`:
   1. `dir := env.Dir()`. Take `lock, err := config.Acquire(filepath.Join(dir, "upgrade.lock"), 2*time.Second)`. If `errors.Is(err, config.ErrLockTimeout)`, print `post-upgrade: another sync is running` to stderr and return nil. Defer `lock.Release()`.
   2. Re-check `needsPostUpgrade(dir)` after taking the lock. If it is false, return nil. This makes the sync run exactly once even when many sessions start together.
   3. `p, err := integrations.ParamsFromEnv(env.Home, dir, env.Getenv)`. `ParamsFromEnv` already sets `p.Binary` to the stable path of the running executable (T4.17). Return any error.
   4. `results, backup, err := integrations.Sync(ctx, p)`. On error, return it (it is logged to `update.log` by the detached parent's redirection).
   5. If any result has `Status == "incomplete"`, print each to stderr and return an error `post-upgrade: incomplete; will retry at next session start` without saving `SeenVersion`.
   6. Otherwise, set `st.SeenVersion = version.Version` and call `update.SaveState(dir, st)`. Print `post-upgrade: synced <n> integrations (backup <ID>)` to stderr. Return nil.
4. `hook_postupgrade_test.go` (package main). Set `version.Version` in tests (restore with `t.Cleanup`). Isolate the writer registry with `defer integrations.ResetForTest()()` (declared in docs/interfaces.md) and register a fake `integrations.Writer` that rewrites `<home>/.cursor/mcp.json` using `integrations.MergeJSONServer` and `integrations.Entry`. Set `integrations.BinaryOverride` to the expected stable path. Tests:
   - `TestNeedsPostUpgradeFalseForDev`
   - `TestNeedsPostUpgradeFalseWithoutStatus`
   - `TestNeedsPostUpgradeTrueOnNewVersion`
   - `TestRunPostUpgradeRewritesStalePath`: the Cursor entry `command` is `/opt/homebrew/Cellar/ajent/0.7.0/bin/ajent` beforehand, and afterwards it equals the stable binary. `state.json` has `seen_version` equal to the test version.
   - `TestRunPostUpgradeOnce`: a second run makes zero writes (compare the file mtime and bytes).
   - `TestRunPostUpgradeConcurrent`: two goroutines. Since both run in-process, hold the lock in the test and call `runPostUpgrade`, which must return nil with the `another sync` message.
   - `TestRunPostUpgradeIncompleteDoesNotMarkSeen`: a writer returns an error, so `seen_version` is unchanged.
   - `TestHookExtraNoStdout`: run `cli.Main(ctx, env, ["hook","session-start"])` with `needsPostUpgrade` true, and replace the `startDetached` seam (declared by T6.3; restore it with `t.Cleanup`). Assert the seam was called with `["post-upgrade"]` and that stdout contains only the hook text.

### Acceptance criteria

- `go test ./cmd/ajent -run 'PostUpgrade|HookExtra' -race -count=1` passes on ubuntu, macos and windows CI.
- `golangci-lint run ./cmd/...` and `gofmt -l cmd` are clean.
- Genuine-red: remove the re-check in step 3.2 and run `TestRunPostUpgradeOnce`. It fails because a second write happens. Restore it and report both outputs.
