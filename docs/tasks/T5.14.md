## T5.14: Obtain the Apple Developer ID and notary API key

### Objective

The `release` environment holds the five secrets that GoReleaser's `notarize.macos` block needs to sign and notarize the darwin binaries: `MACOS_SIGN_P12`, `MACOS_SIGN_PASSWORD`, `MACOS_NOTARY_KEY`, `MACOS_NOTARY_KEY_ID` and `MACOS_NOTARY_ISSUER_ID`. This is a runbook for the maintainer (David). T5.4 consumes the result.

### Read first

- docs/adr/004-release-signing.md
- docs/tasks/T5.4.md

### Scope

Apple Developer account settings, App Store Connect API keys, the Keychain on the maintainer's Mac, and GitHub environment secrets on `ajent-social/ajent-client`. No repository files change.

### Out of scope

- GoReleaser configuration (T5.4).
- Windows Authenticode signing (not planned at launch, ADR 004).

### Steps

1. Confirm an active Apple Developer Program membership (organization or individual) at developer.apple.com > Account > Membership. Record the Team ID.
2. Create a certificate signing request. Open Keychain Access > Certificate Assistant > Request a Certificate From a Certificate Authority. Use your email and the common name `ajent release`, choose "Saved to disk", and save `ajent.certSigningRequest`.
3. Go to developer.apple.com > Certificates, Identifiers and Profiles > Certificates > + > Developer ID Application (G2 Sub-CA). Upload the CSR, download `developerID_application.cer`, and double-click it to add it to the login Keychain.
   Verify: `security find-identity -v -p codesigning | grep "Developer ID Application"` prints one identity with your Team ID in parentheses.
4. Export the identity as .p12. In Keychain Access > My Certificates, right-click "Developer ID Application: ..." > Export, choose `.p12` format, and set a new 32-character random password.
   - `MACOS_SIGN_P12` is the output of `base64 -i ajent-devid.p12` (one line).
   - `MACOS_SIGN_PASSWORD` is the export password.
   Verify: `openssl pkcs12 -in ajent-devid.p12 -nokeys -passin pass:<password> -legacy | grep subject` shows `Developer ID Application`. The `-legacy` flag is needed with OpenSSL 3 for Keychain exports.
5. Create the notary API key. Go to App Store Connect > Users and Access > Integrations > App Store Connect API > Team Keys > +. Name it `ajent notarization` with access `Developer`. Download `AuthKey_<KEYID>.p8`. It can be downloaded only once.
   - `MACOS_NOTARY_KEY` is the output of `base64 -i AuthKey_<KEYID>.p8` (one line).
   - `MACOS_NOTARY_KEY_ID` is the Key ID column.
   - `MACOS_NOTARY_ISSUER_ID` is the Issuer ID shown above the keys table.
   Verify: `xcrun notarytool history --key AuthKey_<KEYID>.p8 --key-id <KEYID> --issuer <ISSUER>` exits 0 (it may list no submissions).
6. Store the secrets in the `release` environment, with values piped from the password manager: `gh secret set MACOS_SIGN_P12 --env release --repo ajent-social/ajent-client`. Repeat for the other four names.
7. Store the `.p12`, its password and the `.p8` in the password manager. Delete the local files with `rm -P`.

### Acceptance criteria

- `gh secret list --env release --repo ajent-social/ajent-client` includes `MACOS_SIGN_P12`, `MACOS_SIGN_PASSWORD`, `MACOS_NOTARY_KEY`, `MACOS_NOTARY_KEY_ID` and `MACOS_NOTARY_ISSUER_ID`.
- The `notarytool history` check in step 5 exits 0.
- No certificate or key file remains on local disk outside the password manager.

### Verification

- `gh secret list --env release --repo ajent-social/ajent-client | grep MACOS_`
- `security find-identity -v -p codesigning | grep -c "Developer ID Application"` prints at least 1 on the machine that created the certificate.
