## T3.11: Add the ajent skills command

### Objective

People and scripts can use the skills catalog from the terminal: `ajent skills search QUERY...` lists matching skills and `ajent skills get ID VERSION` prints one skill's verified Markdown, ready to save or read.

### Read first

- docs/contract.md sections 10 (CLI output) and 14 (skill search, including the CLI lines).
- docs/interfaces.md sections "internal/cli", "cmd/ajent (package main): hooks and seams" and "internal/skills (T3.9)".
- `cmd/ajent/helpers.go` and `cmd/ajent/testenv_test.go` (T2.6), `internal/skills` and `internal/testutil/fakeskills` (T3.9).

### Scope

- `cmd/ajent/cmd_skills.go`
- `cmd/ajent/cmd_skills_test.go`

### Out of scope

- Any other file in `cmd/ajent`, including `main.go` and `helpers.go`.
- Credentials: this command never loads or resolves one.

### Steps

1. In `init()`, register `cli.Command{Name: "skills", Summary: "Search and retrieve skills from the public Ajent skills catalog", Usage: "ajent skills search [--limit N] QUERY... | ajent skills get ID VERSION", Flags: ..., Run: runSkills}`.
2. `runSkills`: the first argument selects `search` or `get`; anything else (or nothing) returns an error wrapping `cli.ErrUsage` (exit 2).
3. `search`: a `flag.FlagSet("skills search", flag.ContinueOnError)` with `--limit` (int, default 5). Join the remaining words with single spaces. Build the client with `skills.New(env.Getenv)`. Print the response with `cli.PrintJSON(env.Stdout, resp)`.
4. `get`: exactly two positional arguments, else `cli.ErrUsage`. Write the verified bytes to `env.Stdout` unchanged.
5. Errors: `skills.ErrInvalidArgument` wraps `cli.ErrUsage`. `ErrUnavailable` gives `skills: unavailable`, `ErrVerificationFailed` gives `skills: verification failed`, and `*RejectedError` gives `skills: request rejected (<code>, HTTP <status>)`, each returned as an error so `cli.Main` prints `ajent: ...` and exits 1. Write nothing to stdout before the operation succeeds.
6. Tests (use `newTestEnv` and `run` from `testenv_test.go`, `fakeskills`, and set `AJENT_SKILLS_ORIGIN` through the env's `Getenv`):
   - `TestSkillsSearchCommand`: exit 0, stdout is indented JSON with the fake results, and the fake recorded `limit=5`.
   - `TestSkillsGetCommand`: exit 0 and stdout equals the stored bytes exactly.
   - `TestSkillsGetTamperedCommand`: exit 1, stderr `ajent: skills: verification failed`, stdout empty.
   - `TestSkillsUsage`: no subcommand, an unknown subcommand, `get` with one argument and `--limit 11` all exit 2 with no request recorded.
   - `TestSkillsNeverResolvesCredential`: the env's `Resolve` fails the test if called.

### Acceptance criteria

- All tests pass with `-race`, `GOOS=windows go vet` is clean and golangci-lint reports 0 issues.
- `ajent help skills` shows the usage line.
- Genuine-red check: print the bytes before checking the error from `Get` and observe `TestSkillsGetTamperedCommand` fail on non-empty stdout. Restore and show it passing. Report both outputs.
