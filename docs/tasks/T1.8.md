## T1.8: Set the private leak denylist secret

### Objective

The `LEAK_DENYLIST` Actions secret holds the private patterns that must never appear in this public repository, so the leak-scan job from T1.5 passes on `main` and blocks future leaks.

### Read first

- docs/adr/001-open-source-client-apache-2.md
- docs/tasks/T1.5.md (how `scripts/leak-scan.sh` reads the secret)

### Scope

- The repository secret `LEAK_DENYLIST` on `ajent-social/ajent`. No files in the repository change.

### Out of scope

- Committing the denylist, or any pattern from it, anywhere in this repository, in issues, or in PR text.

### Steps

1. On your own machine, outside any repository, create a plain-text file with one extended regular expression per line. Include: private and staging hostnames of the service, names of internal projects and repositories, internal infrastructure identifiers, maintainer home-directory prefixes, private IP ranges you use, and customer names. Match case-insensitively where needed with `(?i)`-free alternations such as `[Ss]ecret`.
2. Check that the patterns match what you expect: `grep -rEnf <file> <path to a private checkout>` should find hits there, and `grep -rEnf <file> .` in this repository should find none.
3. Store the secret: `gh secret set LEAK_DENYLIST -R ajent-social/ajent < <file>`.
4. Securely delete the local file, or keep it only in your password manager.
5. Re-run the latest leak-scan workflow on `main`: `gh run rerun --failed -R ajent-social/ajent $(gh run list -R ajent-social/ajent --workflow safety.yml --branch main --limit 1 --json databaseId --jq '.[0].databaseId')`.

### Acceptance criteria

- `gh secret list -R ajent-social/ajent` lists `LEAK_DENYLIST`.
- The most recent leak-scan run on `main` is green.
- No pattern appears in the repository, its history, or any workflow log (the script prints only file:line).

### Verification

- `gh secret list -R ajent-social/ajent | grep LEAK_DENYLIST`
- `gh run list -R ajent-social/ajent --workflow safety.yml --branch main --limit 1`
