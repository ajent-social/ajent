## T1.4: Add the CI workflow

### Objective

Every push to `main` and every pull request runs these checks on ubuntu, macos and windows: formatting, vet, lint, race tests, vulnerability scanning, the license-header check and a cross-compile matrix. All actions are pinned by commit SHA and the workflow has read-only permissions.

### Read first

- docs/adr/002-go-stdlib-single-binary.md (CGO off, target platforms)
- `Makefile` (from T1.1)

### Scope

- `.github/workflows/ci.yml`
- `.golangci.yml`

### Out of scope

- Leak scanning, gitleaks and DCO (T1.5). Release workflows (E5). Markdown and link checks (T7.6).
- Changing Go source to satisfy the linters beyond trivial fixes in files created by T1.1. If a linter flags another task's file, disable nothing. Report it in the PR body instead.

### Steps

1. Resolve pinned SHAs for each action with `gh api repos/<owner>/<repo>/git/ref/tags/<tag> --jq .object.sha`. If the result is an annotated tag object, follow it with `gh api repos/<owner>/<repo>/git/tags/<sha> --jq .object.sha`. Pin as `uses: owner/repo@<40-char sha> # <tag>`. Find the latest release tags with `gh release view -R <owner>/<repo> --json tagName --jq .tagName`. Actions to pin:
   - `actions/checkout` (latest v4 or v5 tag)
   - `actions/setup-go` (latest v5 or v6 tag)
   - `golangci/golangci-lint-action` (latest v6 or v8 tag). Set its `version:` input to the latest golangci-lint v2 release, found with `gh release view -R golangci/golangci-lint --json tagName`.
2. `.github/workflows/ci.yml`:
   - `name: ci`
   - `on: push: branches: [main]` and `pull_request:`
   - Top-level `permissions: contents: read`
   - `concurrency: group: ci-${{ github.ref }}`, `cancel-in-progress: true`
   - Jobs, each with `timeout-minutes: 15`:
     - `format` (ubuntu-latest): checkout, setup-go with `go-version-file: go.mod`, then `test -z "$(gofmt -l .)" || { gofmt -l .; exit 1; }`
     - `vet` (ubuntu-latest): `go vet ./...` and `GOOS=windows go vet ./...` and `GOOS=darwin go vet ./...`
     - `lint` (ubuntu-latest): golangci-lint-action with the pinned version
     - `test`: `strategy.matrix.os: [ubuntu-latest, macos-latest, windows-latest]`, `fail-fast: false`, run `go test -race -count=1 ./...`, with `shell: bash` on every step so Windows behaves the same
     - `vuln` (ubuntu-latest): `go run golang.org/x/vuln/cmd/govulncheck@latest ./...`
     - `license` (ubuntu-latest): `scripts/check-license-headers.sh .`, guarded with `if [ -x scripts/check-license-headers.sh ]; then ...; else echo "license check not present yet"; fi` so that this task does not depend on T1.2 landing first
     - `cross-compile` (ubuntu-latest): matrix `goos: [darwin, linux, windows]`, `goarch: [amd64, arm64]`, env `CGO_ENABLED: "0"`, run `GOOS=${{ matrix.goos }} GOARCH=${{ matrix.goarch }} go build -trimpath -o /dev/null ./cmd/ajent`
3. `.golangci.yml` (golangci-lint v2 config format):

   ```yaml
   version: "2"
   linters:
     default: standard
     enable:
       - gosec
       - errorlint
       - misspell
       - revive
       - bodyclose
       - unconvert
   formatters:
     enable:
       - gofmt
   ```

   If the pinned golangci-lint major version is v1, write the v1 equivalent instead: `linters: enable: [...]`, and `gofmt` in the linters list. Record which one you used in the PR body.
4. Run `golangci-lint run` locally if it is installed. If it is not, install the pinned version with `go install github.com/golangci/golangci-lint/v2/cmd/golangci-lint@<tag>` and run it.
5. Open a draft PR with the workflow. All jobs must pass on the T1.1 skeleton.

### Acceptance criteria

- On the PR, jobs `format`, `vet`, `lint`, `test (ubuntu-latest)`, `test (macos-latest)`, `test (windows-latest)`, `vuln`, `license` and the six `cross-compile` jobs all pass.
- `grep -E 'uses: [^@]+@[0-9a-f]{40}' .github/workflows/ci.yml | wc -l` equals the total number of `uses:` lines.
- Genuine-red check: push a commit to a throwaway branch (not the PR branch) that adds a deliberately misformatted Go file, `cmd/ajent/zz_bad.go` containing `package main\nfunc  zz( ){}`. Open a throwaway draft PR, observe the `format` job fail, then close the PR and delete the branch. Report the failing job URL and the passing job URL from the real PR.

### Verification

```bash
gh workflow view ci
gh pr checks <pr-number> --watch
grep -c 'uses:' .github/workflows/ci.yml
grep -cE 'uses: [^@]+@[0-9a-f]{40}' .github/workflows/ci.yml
```
