## T7.3: Generate the command and tool references

### Objective

`docs/commands.md` and `docs/mcp-tools.md` are generated from the registered CLI commands and MCP tools. `make docs` regenerates them, and CI fails when the committed files are stale.

### Read first

- docs/interfaces.md, sections "internal/cli" (`Register`, `Commands`) and "internal/mcp" (`Register`, `Tools`)
- docs/tasks/T2.6.md and docs/tasks/T3.2.md

### Scope

- `cmd/ajent/cmd_gendocs.go`
- `cmd/ajent/cmd_gendocs_test.go`
- `internal/gendocs/gendocs.go`
- `internal/gendocs/gendocs_test.go`
- `docs/commands.md` (generated)
- `docs/mcp-tools.md` (generated)
- `Makefile` (change only the `docs` target)
- `.github/workflows/docs-drift.yml`

### Out of scope

- Editing command or tool definitions. If a summary or description is missing, generate a placeholder row with `(no summary)` and list it in the PR body.
- Hand-written docs (T7.2).

### Steps

1. Why a hidden command: CLI commands are registered from `init()` functions in package `main` (`cmd/ajent/cmd_*.go`), so only code in package `main` sees the complete list. MCP tools register in `internal/mcp`.
2. `internal/gendocs/gendocs.go` (package `gendocs`, SPDX header):
   - `func Commands(w io.Writer, cmds []cli.Command) error` writes:

     ```markdown
     # Command reference

     <!-- Generated by `make docs`. Do not edit. -->

     | Command | Description |
     |---------|-------------|
     | `ajent <name>` | <Summary> |
     ```

     One row per command in the order `cli.Commands()` returns (sorted by name, hidden commands excluded). Escape `|` in summaries as `\|`.
   - `func Tools(w io.Writer, tools []mcp.Tool) error` writes `# MCP tool reference`, the same generated comment, then for each tool a `## <name>` section with the description paragraph, the line `Read-only: yes|no. Destructive: yes|no.`, and a `### Input` table with columns Field, Type, Required and Description. Build the table from `InputSchema` by decoding `properties`, `required`, and each property's `type` and `description`. Sort properties by name.
   - Output ends with exactly one trailing newline and uses LF line endings.
3. `cmd/ajent/cmd_gendocs.go` registers a hidden command:
   `cli.Register(cli.Command{Name: "gendocs", Hidden: true, Summary: "Generate reference docs", Run: ...})`. `Run` takes one argument, the output directory (default `docs`), and writes `commands.md` and `mcp-tools.md` there using `config`-independent `os.WriteFile` with mode 0644.
4. `Makefile`: replace the body of the `docs` target with `go run ./cmd/ajent gendocs docs`.
5. `internal/gendocs/gendocs_test.go`:
   - `TestCommandsTable` uses two fake `cli.Command` values and compares the output to an inline golden string.
   - `TestCommandsEscapesPipe`.
   - `TestToolsSchemaTable` uses a fake tool with properties `query` (string, required) and `limit` (integer), and compares to an inline golden string.
   - `TestToolsAnnotations`.
6. `cmd/ajent/cmd_gendocs_test.go`: `TestGendocsUpToDate` runs the gendocs `Run` function into `t.TempDir()` and compares byte-for-byte with `../../docs/commands.md` and `../../docs/mcp-tools.md`. On mismatch, fail with `docs are stale; run make docs`.
7. `.github/workflows/docs-drift.yml`: `on: pull_request` and `push: branches: [main]`, with `permissions: contents: read`. One job `docs-drift` (ubuntu-latest) runs `make docs` then `git diff --exit-code docs/commands.md docs/mcp-tools.md`. Pin actions by SHA as described in docs/tasks/T1.4.md.
8. Run `make docs` and commit the generated files.
9. Add one line to the PR body: "Any task that adds a command or tool must run `make docs`."

### Acceptance criteria

- `make docs` writes both files. Running it twice produces no diff.
- `go test ./internal/gendocs/ ./cmd/ajent/ -run 'TestCommands|TestTools|TestGendocs' -count=1` passes.
- The CI job `docs-drift` passes on the PR.
- Genuine-red check: append the line `stale` to `docs/commands.md`, run `go test ./cmd/ajent/ -run TestGendocsUpToDate` and observe the failure message `docs are stale; run make docs`. Run `make docs` and observe the test pass. Report both outputs.

### Verification

```bash
make docs && git diff --stat docs/commands.md docs/mcp-tools.md
go test -count=1 -v ./internal/gendocs/ ./cmd/ajent/ -run 'TestCommands|TestTools|TestGendocs'
go vet ./internal/gendocs/ ./cmd/ajent/
```
