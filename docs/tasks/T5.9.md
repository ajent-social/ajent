## T5.9: Write the install scripts

### Split (2026-09-24)

This task does not wait for the release key (T5.3b). In `scripts/install.sh`, put the embedded PEM between the lines `# ---- BEGIN release PEM (T5.3b) ----` and `# ---- END release PEM (T5.3b) ----`, and leave the heredoc body empty. When the embedded PEM is empty and `AJENT_RELEASE_PUBKEY_FILE` is unset, `verify_signature` dies with `no release key is embedded in this installer`, even if OpenSSL is missing, so an unkeyed installer never installs anything. Tests always pass `AJENT_RELEASE_PUBKEY_FILE`. `install.ps1` verifies through the downloaded binary's `ajent verify-release`, which already fails closed until T5.3b embeds the key. T5.3b fills the block with the exact contents of `packaging/ajent-release.pub.pem`.

### Objective

`scripts/install.sh` (macOS and Linux, POSIX sh) and `scripts/install.ps1` (Windows PowerShell 5.1 and PowerShell 7) download a release archive, verify it against `checksums.txt`, check the Ed25519 signature when a verifier is available, install `ajent`, record the install method in `install.json`, and start `ajent setup` when a terminal is attached. Both refuse an archive whose SHA-256 does not match. A test harness runs both against locally served snapshot artifacts on ubuntu, macos and windows CI.

### Steps

1. Environment variables, the same for both scripts. Document them in a header comment:
   - `AJENT_VERSION`: version to install (`0.7.0` or `v0.7.0`). The default is the latest stable release.
   - `AJENT_INSTALL_DIR`: the default is `$HOME/.local/bin` (sh) or `$env:LOCALAPPDATA\Programs\ajent` (ps1).
   - `AJENT_CONFIG_DIR`: the default is `$HOME/.aj` (sh) or `$HOME\.aj` (ps1).
   - `AJENT_NO_SETUP=1`: skip running `ajent setup`.
   - `AJENT_REQUIRE_SIGNATURE=1`: fail instead of warning when the signature cannot be checked.
   - `AJENT_DOWNLOAD_BASE`: the default is `https://github.com/ajent-social/ajent-client/releases/download`. Used by tests and mirrors. When set, `AJENT_VERSION` is required.
   - `AJENT_RELEASE_PUBKEY_FILE`: a PEM that replaces the embedded key. For tests only; the header comment says so.
2. `scripts/install.sh` structure. Line 1 is `#!/bin/sh`, line 2 is the SPDX comment, then `set -eu`. All logic lives in functions, and the last line is `main "$@"`, so a truncated download never executes a partial script. Functions and behavior:
   1. `say` prints to stderr prefixed `ajent-install:`. `die` calls `say` and exits 1.
   2. `need_cmd` checks `command -v`. The script needs `uname`, `tar`, `mktemp` and one of `curl` or `wget`. For hashing it needs `sha256sum`, or `shasum -a 256` as a fallback.
   3. `download <url> <out>`: `curl -fsSL --proto '=https,http' --retry 3 -o "$2" "$1"`, or `wget -q -O "$2" "$1"`.
   4. `detect_os`: `uname -s` gives `Darwin` -> `darwin` and `Linux` -> `linux`. Anything else dies with `unsupported OS <x>; on Windows run: irm https://ajent.social/install.ps1 | iex`.
   5. `detect_arch`: `uname -m` gives `x86_64|amd64` -> `amd64` and `arm64|aarch64` -> `arm64`. Anything else dies. On darwin, when `sysctl -n sysctl.proc_translated 2>/dev/null` prints `1` (Rosetta), use `arm64`.
   6. `resolve_version`: strip a leading `v`. If empty and `AJENT_DOWNLOAD_BASE` is unset, resolve the latest release via the redirect: `curl -fsSLI -o /dev/null -w '%{url_effective}' https://github.com/ajent-social/ajent-client/releases/latest`, then take the part after `/tag/v`. With wget, parse the last `Location:` header of `wget -S --spider --max-redirect=5`. Validate against `^[0-9]+\.[0-9]+\.[0-9]+(-[0-9A-Za-z.-]+)?$` with `grep -Eq`, and die otherwise.
   7. `verify_sha256 <file> <name> <checksums>`: find the line whose second field is `<name>` (or `*<name>`) with `awk`, compute the hash, compare, and die with `checksum mismatch for <name>` on mismatch or when the name is not listed.
   8. `verify_signature <checksums> <sig>`: write the embedded PEM (a heredoc holding the exact contents of `packaging/ajent-release.pub.pem`), or copy `AJENT_RELEASE_PUBKEY_FILE`, into the temp dir. If `openssl` exists and `openssl pkeyutl -help 2>&1 | grep -q rawin`, decode with `openssl base64 -d -A -in <sig> -out sig.bin` and verify with `openssl pkeyutl -verify -pubin -inkey key.pem -rawin -in <checksums> -sigfile sig.bin`. Die with `release signature does not verify` on failure. When no suitable openssl exists: die if `AJENT_REQUIRE_SIGNATURE=1`, otherwise print `signature not checked (OpenSSL 3 not found); SHA-256 checksum verified`.
   9. `main`:
      1. Create a temp dir with `mktemp -d` and `trap 'rm -rf "$tmp"' EXIT INT TERM`.
      2. Set `base=${AJENT_DOWNLOAD_BASE:-https://github.com/ajent-social/ajent-client/releases/download}` and `name=ajent_${v}_${os}_${arch}.tar.gz`.
      3. Download `$base/v$v/$name`, `$base/v$v/checksums.txt` and `$base/v$v/checksums.txt.sig`.
      4. Run `verify_signature`, then `verify_sha256`.
      5. Run `tar -xzf "$tmp/$name" -C "$tmp" ajent`.
      6. Run `mkdir -p "$dir"` (die with `cannot create $dir; set AJENT_INSTALL_DIR to a writable directory` on failure), then `cp "$tmp/ajent" "$dir/.ajent.new" && chmod 0755 "$dir/.ajent.new" && mv -f "$dir/.ajent.new" "$dir/ajent"`.
      7. Write `$cfg/install.json` (with `umask 077` and `mkdir -p "$cfg"`, `chmod 700 "$cfg"`) containing one line: `{"method":"script","version":"<v>","path":"<dir>/ajent","installed_at":"<date -u +%Y-%m-%dT%H:%M:%SZ>"}`.
      8. Print `ajent <v> installed to <dir>/ajent`.
      9. If `$dir` is not in `PATH`, print `Add it to your PATH: echo 'export PATH="<dir>:$PATH"' >> ~/.profile` (use `~/.zshrc` when `$SHELL` ends in `zsh`).
      10. If `AJENT_NO_SETUP` is not `1` and `/dev/tty` is readable and writable, run `"$dir/ajent" setup </dev/tty >/dev/tty 2>&1 || say "setup did not finish; run: ajent setup"`. Otherwise print `Next: run "ajent setup" to connect your coding agents.`
3. `scripts/install.ps1` has the SPDX comment on line 1, then `$ErrorActionPreference = 'Stop'`. All logic lives in `function Install-Ajent { ... }` and the last line is `Install-Ajent`. It must run on Windows PowerShell 5.1: no `??`, no ternary, no `-AsHashtable`, and it sets `[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12`. Behavior:
   1. Arch: `$env:PROCESSOR_ARCHITEW6432`, else `$env:PROCESSOR_ARCHITECTURE`. `AMD64` maps to `amd64` and `ARM64` to `arm64`. Anything else throws.
   2. Version: when `AJENT_VERSION` is empty and `AJENT_DOWNLOAD_BASE` is unset, use `(Invoke-RestMethod https://api.github.com/repos/ajent-social/ajent-client/releases/latest -Headers @{ 'User-Agent' = 'ajent-install' }).tag_name`, then strip `v`. Validate with the same regex as install.sh.
   3. Download `ajent_<v>_windows_<arch>.zip`, `checksums.txt` and `checksums.txt.sig` to a temp dir (`New-Item -ItemType Directory (Join-Path $env:TEMP ("ajent-" + [guid]::NewGuid()))`) with `Invoke-WebRequest -UseBasicParsing -OutFile`.
   4. SHA-256: compare `(Get-FileHash -Algorithm SHA256 $zip).Hash.ToLower()` with the checksums line for the zip name. Throw `checksum mismatch for <name>` on mismatch.
   5. Signature: Windows PowerShell has no built-in Ed25519. After extraction, run `& $newExe verify-release --checksums $checksums --sig $sig --file $zip` and require exit 0. The installer's output must say this checks integrity with the downloaded binary. Users who need independent verification should follow docs/verifying-releases.md. If `AJENT_REQUIRE_SIGNATURE` is `1` and `openssl.exe` 3.x is on PATH, also verify with OpenSSL as in install.sh.
   6. Extract with `Expand-Archive -Force` to the temp dir. Create the install dir. If `ajent.exe` exists there, remove any stale `ajent.exe.old`, then rename the existing exe to `ajent.exe.old` (a running exe can be renamed). Move the new exe in.
   7. Add the install dir to the user PATH if absent. Read it with `[Environment]::GetEnvironmentVariable('Path','User')`, write it with `SetEnvironmentVariable(..., 'User')`, and also prepend it to `$env:Path` for the current session.
   8. Write `install.json` (same fields as install.sh, `path` with backslashes JSON-escaped via `ConvertTo-Json -Compress`) to `$env:AJENT_CONFIG_DIR`, or `$HOME\.aj` when that is unset.
   9. Unless `AJENT_NO_SETUP` is `1`, and when `[Environment]::UserInteractive` is true and `[Console]::IsInputRedirected` is false, run `& $exe setup`. Otherwise print the next step.
4. `scripts/test-install.sh` (SPDX header, `set -eu`). Usage: `test-install.sh <dist-dir> <version>`. It:
   1. Generates a throwaway key with `go run ./internal/tools/signchecksums -keygen "$tmp/k"`.
   2. Re-signs: `RELEASE_ED25519_KEY=$(cat "$tmp/k.seed") go run ./internal/tools/signchecksums -in "$dist/checksums.txt" -out "$dist/checksums.txt.sig"`.
   3. Builds the serve tree `$tmp/www/v<version>/` with copies of the archives, `checksums.txt` and `checksums.txt.sig`.
   4. Starts `python3 -m http.server 8766 --directory "$tmp/www"` in the background and kills it on exit.
   5. Case `ok`: runs `AJENT_DOWNLOAD_BASE=http://127.0.0.1:8766 AJENT_VERSION=<version> AJENT_INSTALL_DIR=$tmp/bin AJENT_CONFIG_DIR=$tmp/cfg AJENT_NO_SETUP=1 AJENT_RELEASE_PUBKEY_FILE=$tmp/k.pem sh scripts/install.sh`. Asserts `$tmp/bin/ajent version --json` has the expected version, `$tmp/cfg/install.json` has `"method":"script"`, and on unix the mode is 0600.
   6. Case `bad-checksum`: copies the serve tree, appends a byte to the archive, and installs into `$tmp/bin2`. Asserts a non-zero exit, output containing `checksum mismatch`, and no `$tmp/bin2/ajent`.
   7. Case `bad-signature` (only when OpenSSL 3 is present): replaces `checksums.txt.sig` with a signature from a second throwaway key. Asserts a non-zero exit and `release signature does not verify`.
   8. Case `require-signature-without-openssl`: runs with `PATH` stripped of openssl (a temp PATH dir containing symlinks to only the needed tools) and `AJENT_REQUIRE_SIGNATURE=1`. Asserts a non-zero exit.
   9. Prints `PASS <case>` or `FAIL <case>` per case and exits non-zero on any failure.
5. `scripts/test-install.ps1`: the same cases for install.ps1 (ok and bad-checksum; bad-signature uses the `verify-release` path, so sign with a key the snapshot binary does not trust). Build the snapshot binaries for this test with `-X github.com/ajent-social/ajent-client/internal/update.extraKeyB64=<k.pub>` by running GoReleaser with `--skip=sign,notarize,publish` and an env var that the base ldflags do not read. Instead, build the Windows zip for the test yourself: `go build -ldflags "-X ...extraKeyB64=$(Get-Content k.pub)" -o ajent.exe ./cmd/ajent`, `Compress-Archive` it as `ajent_<v>_windows_amd64.zip`, then generate `checksums.txt` with `Get-FileHash` lines in `<hash>  <name>` format and sign it. Assert the PATH update in a child `pwsh` that reads `[Environment]::GetEnvironmentVariable('Path','User')`. Undo the PATH change in a `finally` block.
6. `.github/workflows/install-scripts.yml`: on `pull_request` with paths `scripts/install.*`, `scripts/test-install.*`, `internal/tools/signchecksums/**` and `.github/workflows/install-scripts.yml`. `permissions: contents: read`. Jobs:
   - `unix`: a matrix of `ubuntu-latest` and `macos-latest`. Setup Go, download syft, run the GoReleaser snapshot with `--skip=sign,notarize,publish`, run `sh scripts/test-install.sh dist "$(jq -r .version dist/metadata.json)"`, and run `shellcheck scripts/install.sh scripts/test-install.sh`. On ubuntu, also run `dash -n scripts/install.sh` and `busybox sh -n scripts/install.sh` (install busybox).
   - `windows`: `windows-latest`. Run `pwsh -File scripts/test-install.ps1` and `powershell -File scripts/test-install.ps1` (Windows PowerShell 5.1), plus `Invoke-ScriptAnalyzer -Path scripts/install.ps1,scripts/test-install.ps1 -Severity Warning,Error` with zero findings.
   - SHA-pin all actions.

### Acceptance criteria

- `install-scripts.yml` is green on ubuntu, macos and windows with every `PASS` case printed. Record the run URL.
- `shellcheck`, `dash -n`, `busybox sh -n` and PSScriptAnalyzer report no findings. `actionlint` passes.
- Running `sh scripts/install.sh` with `AJENT_VERSION=0.0.0-missing` and a local base fails with a clear download error and leaves no files in the install dir.
- Genuine-red: make `verify_sha256` in install.sh always succeed, run `sh scripts/test-install.sh`, and observe `FAIL bad-checksum`. Restore it and report both outputs.
