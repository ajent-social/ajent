## T5.10: Serve the install scripts from pkg.ajent.social

### Objective

Every publish of `ajent-social/packages` copies `scripts/install.sh` and `scripts/install.ps1` from the released tag of `ajent-social/ajent` to the site root. `https://pkg.ajent.social/install.sh` and `https://pkg.ajent.social/install.ps1` then serve byte-identical copies of the scripts at the latest stable tag. Until the hosted `ajent.social` URLs are switched over in E8, these are the canonical one-liner URLs.

### Read first

- docs/tasks/T5.7.md (packages repository layout and `publish.yml`)
- docs/tasks/T5.9.md (the scripts)
- docs/adr/003-distribution-channels.md

### Scope

Work in a separate clone of `ajent-social/packages` (`gh repo clone ajent-social/packages ../packages`) on a branch, and open a PR there. Modify only:

- `.github/workflows/publish.yml` (add steps)
- `scripts/build-repo.sh` (copy the scripts when present)
- `scripts/test-repo.sh` (add assertions)
- `README.md` and `static/index.html` (add the one-liners)
Nothing changes in `ajent-social/ajent`.

### Out of scope

- Changes to the scripts themselves (T5.9). The ajent.social redirects (E8). Serving scripts for prereleases.

### Steps

1. In `publish.yml`, after the release download step and only when the release is not a prerelease (`jq -r .prerelease release.json` is `false`), fetch the scripts at the tag. Run `gh api "repos/ajent-social/ajent/contents/scripts/install.sh?ref=$TAG" -H "Accept: application/vnd.github.raw" > incoming/install.sh`, and the same for `install.ps1`.
2. Integrity check. The scripts are not in `checksums.txt`, so compare their git blob SHA to the tagged tree. Fetch `gh api "repos/ajent-social/ajent/contents/scripts/install.sh?ref=$TAG" -q .sha`, compute `git hash-object incoming/install.sh`, and fail the job on any difference. Repeat for `install.ps1`.
3. In `build-repo.sh`, if `<incoming-dir>/install.sh` exists, copy it to `<site-dir>/install.sh` with mode 0644. Do the same for `install.ps1`. Otherwise leave any existing site copies unchanged, so prereleases never replace them.
4. In `test-repo.sh`, add a case that places fixture `install.sh` and `install.ps1` files in `incoming/`, runs `build-repo.sh`, and asserts `cmp` equality in the site. Add a second run without the files and assert the site copies are unchanged.
5. Add these one-liners to `README.md` and `static/index.html`:
   - `curl -fsSL https://pkg.ajent.social/install.sh | sh`
   - `irm https://pkg.ajent.social/install.ps1 | iex`
6. After merge and the next stable publish, confirm with `curl -fsSL https://pkg.ajent.social/install.sh | cmp - <(gh api "repos/ajent-social/ajent/contents/scripts/install.sh?ref=<tag>" -H "Accept: application/vnd.github.raw")`. The full install from this URL on a clean machine is verified by T5.12 once the ajent repository is public (E8).

### Acceptance criteria

- `scripts/test-repo.sh` passes with the new cases in `test.yml` CI of the packages repository.
- `shellcheck scripts/*.sh` and `actionlint` pass.
- After the first stable publish, the `cmp` command in step 6 exits 0 for both scripts. Before any stable release exists, record this item as pending, not passed.
- Genuine-red: in `test-repo.sh`, modify the fixture `install.sh` after `build-repo.sh` copies it. The `cmp` assertion fails. Restore it and report both outputs.

### Verification

- In the packages clone: `shellcheck scripts/*.sh && sh scripts/test-repo.sh`
- `go run github.com/rhysd/actionlint/cmd/actionlint@latest .github/workflows/publish.yml`
- After a stable release: `curl -fsSI https://pkg.ajent.social/install.sh`
