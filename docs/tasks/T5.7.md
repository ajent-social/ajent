## T5.7: Build the signed APT and DNF repositories on GitHub Pages

### Objective

The public repository `ajent-social/packages` rebuilds a GPG-signed APT repository and a signed DNF/YUM repository whenever the ajent release workflow dispatches a `release-published` event. The result is served by GitHub Pages at `https://pkg.ajent.social`. On clean containers, `apt-get install ajent` (Debian, Ubuntu) and `dnf install ajent` (Fedora) succeed with signature checking on. The site also serves `gpg.key`, the release public key, `latest.json`, `ajent.sources` and `ajent.repo`.

### Scope

All files live in the separate repository `ajent-social/packages`, not in this repository. Clone it into a new directory outside this checkout (`gh repo clone ajent-social/packages ../packages`), work on a branch there, and open a PR in that repository. Create in `ajent-social/packages`:

- `scripts/build-repo.sh`
- `scripts/test-repo.sh`
- `tests/fixtures/nfpm.yaml`
- `static/gpg.key`, `static/ajent-release.pub`, `static/ajent-release.pub.pem`, `static/ajent.sources`, `static/ajent.repo`, `static/index.html`, `static/CNAME`
- `.github/workflows/publish.yml`
- `.github/workflows/test.yml`
- `README.md` (replace the stub)
In this repository (`ajent-social/ajent-client`), change nothing.

### Out of scope

- Serving install scripts (T5.10 adds them to `static/` and the build).
- Dispatching the event from the ajent release workflow (T5.11).
- Package contents (T5.6).

### Steps

1. Site layout (fixed contract; T5.10, T5.12 and T6.2 depend on it):

   ```text
   /CNAME                       pkg.ajent.social
   /index.html                  short install instructions
   /gpg.key                     ASCII-armored package signing public key
   /ajent-release.pub           raw base64 Ed25519 release public key + newline
   /ajent-release.pub.pem       PEM of the same key
   /latest.json                 {"version":"0.7.0","tag":"v0.7.0","prerelease":false,"assets":{"<name>":"<url>",...}}
   /ajent.sources               deb822 APT source
   /ajent.repo                  DNF/YUM repo file
   /apt/pool/main/a/ajent/*.deb
   /apt/dists/stable/Release, InRelease, Release.gpg
   /apt/dists/stable/main/binary-amd64/Packages, Packages.gz
   /apt/dists/stable/main/binary-arm64/Packages, Packages.gz
   /rpm/*.rpm                   signed with rpmsign
   /rpm/repodata/repomd.xml, repomd.xml.asc, ...
   ```

2. Static files:
   - `static/ajent.sources`:

     ```text
     Types: deb
     URIs: https://pkg.ajent.social/apt
     Suites: stable
     Components: main
     Signed-By: /usr/share/keyrings/ajent.gpg
     ```

   - `static/ajent.repo`:

     ```ini
     [ajent]
     name=ajent
     baseurl=https://pkg.ajent.social/rpm
     enabled=1
     gpgcheck=1
     repo_gpgcheck=1
     gpgkey=https://pkg.ajent.social/gpg.key
     ```

   - `static/gpg.key`, `static/ajent-release.pub` and `static/ajent-release.pub.pem` come verbatim from the T5.0 hand-off and `packaging/ajent-release.pub.pem` in the ajent repository. If the T5.0 keys are unavailable, stop and report blocked on T5.0.
   - `static/CNAME` contains `pkg.ajent.social`.
   - `static/index.html`: a plain HTML5 page (no external assets) with the title `ajent packages` and the install commands from step 8.
3. `scripts/build-repo.sh` (POSIX sh, SPDX header, `set -eu`). Usage: `build-repo.sh <incoming-dir> <site-dir> <gpg-key-id> [<release-json>]`. It:
   1. Copies `static/*` into `<site-dir>/`.
   2. Moves `<incoming-dir>/*.deb` to `<site-dir>/apt/pool/main/a/ajent/` and `*.rpm` to `<site-dir>/rpm/`.
   3. Prunes each of the four sets (deb amd64, deb arm64, rpm x86_64, rpm aarch64) to the 5 newest versions by `sort -V` on the version part of the file name.
   4. Signs every unsigned rpm with `rpmsign --addsign --define "_gpg_name <gpg-key-id>"`. Use `--define "_gpg_sign_cmd_extra_args --pinentry-mode loopback --passphrase-file <file>"` when `GPG_PASSPHRASE_FILE` is set.
   5. Runs `createrepo_c --update <site-dir>/rpm`, then `gpg --batch --yes --local-user <id> --detach-sign --armor <site-dir>/rpm/repodata/repomd.xml`.
   6. For each arch (amd64, arm64): `(cd <site-dir>/apt && apt-ftparchive --arch <arch> packages pool/main > dists/stable/main/binary-<arch>/Packages && gzip -9kf dists/stable/main/binary-<arch>/Packages)`.
   7. Writes the Release file: `apt-ftparchive -o APT::FTPArchive::Release::Origin=ajent -o APT::FTPArchive::Release::Label=ajent -o APT::FTPArchive::Release::Suite=stable -o APT::FTPArchive::Release::Codename=stable -o APT::FTPArchive::Release::Architectures="amd64 arm64" -o APT::FTPArchive::Release::Components=main release <site-dir>/apt/dists/stable > <site-dir>/apt/dists/stable/Release`. Origin and Label `ajent` are required for unattended-upgrades (T6.7).
   8. Signs it: `gpg --batch --yes --local-user <id> --clearsign -o InRelease Release` and `gpg --batch --yes --local-user <id> -abs -o Release.gpg Release`.
   9. If `<release-json>` is given and its `prerelease` is false, writes `<site-dir>/latest.json` from it with `jq '{version: (.tag_name|ltrimstr("v")), tag: .tag_name, prerelease: .prerelease, assets: (.assets | map({(.name): .browser_download_url}) | add)}'`.
   The script is idempotent: running it twice with no new packages produces the same package set.
4. `tests/fixtures/nfpm.yaml`: an nFPM config that packages a two-line shell script `#!/bin/sh\necho "ajent-fixture ${VERSION}"` as `/usr/bin/ajent`, with the version from env `VERSION` and arch from env `ARCH`.
5. `scripts/test-repo.sh` (SPDX header, `set -eu`, needs `podman` or `docker`, `gpg`, `apt-utils`, `createrepo-c` and `rpm`; in CI it runs on `ubuntu-24.04`):
   1. Creates a throwaway GPG home and key (`GNUPGHOME=$(mktemp -d)`, `gpg --batch --passphrase '' --quick-gen-key "test <test@example.invalid>" rsa3072 sign 1d`) and uses the resulting key instead of `static/gpg.key` in the test site.
   2. Builds fixture packages for versions 0.0.1 to 0.0.7 (amd64 deb and rpm) with `go run github.com/goreleaser/nfpm/v2/cmd/nfpm@latest pkg --config tests/fixtures/nfpm.yaml --packager deb|rpm --target incoming/`.
   3. Runs `build-repo.sh` into a temporary site.
   4. Asserts that exactly 5 debs and 5 rpms remain (0.0.3 to 0.0.7).
   5. Serves the site with `python3 -m http.server 8765 --directory <site>` and runs containers with `--network host`:
      - `debian:stable` and `ubuntu:24.04`: install the test key to `/usr/share/keyrings/ajent.gpg` (dearmored), write an `ajent.sources` pointing at `http://127.0.0.1:8765/apt`, run `apt-get update && apt-get install -y ajent && ajent`, and assert the output is `ajent-fixture 0.0.7`.
      - `fedora:latest`: write a repo file pointing at `http://127.0.0.1:8765/rpm` with `gpgcheck=1 repo_gpgcheck=1` and the test key, then run `dnf install -y ajent && ajent`, asserting the same output.
6. `.github/workflows/test.yml`: on `pull_request` and `push` to `main`, runs `shellcheck scripts/*.sh`, installs `apt-utils createrepo-c rpm gnupg`, and runs `scripts/test-repo.sh`. `permissions: contents: read`. SHA-pin actions.
7. `.github/workflows/publish.yml`:
   - Triggers: `repository_dispatch: types: [release-published]` (payload `{"tag": "vX.Y.Z"}`) and `workflow_dispatch` with input `tag`.
   - `permissions: contents: write`. `concurrency: {group: publish, cancel-in-progress: false}`.
   - Steps:
     1. Checkout `main`. Checkout `gh-pages` into `site/`. If the branch does not exist, create an orphan branch and an empty `site/`.
     2. Install tools.
     3. Import `PACKAGES_GPG_KEY` with `gpg --batch --import` and write the passphrase to a 0600 temp file for `GPG_PASSPHRASE_FILE`.
     4. `TAG=${{ github.event.client_payload.tag || inputs.tag }}`. Validate it against `^v[0-9]+\.[0-9]+\.[0-9]+(-[0-9A-Za-z.-]+)?$`.
     5. `gh release download "$TAG" --repo ajent-social/ajent-client --dir incoming --pattern '*.deb' --pattern '*.rpm' --pattern 'checksums.txt' --pattern 'checksums.txt.sig'`.
     6. Verify the checksums signature with OpenSSL 3: `base64 -d incoming/checksums.txt.sig > sig.bin && openssl pkeyutl -verify -pubin -inkey static/ajent-release.pub.pem -rawin -in incoming/checksums.txt -sigfile sig.bin`.
     7. Run `(cd incoming && sha256sum --ignore-missing -c checksums.txt)`. Fail the job on any mismatch.
     8. `gh api repos/ajent-social/ajent-client/releases/tags/$TAG > release.json`, then run `scripts/build-repo.sh incoming site <keyid> release.json`.
     9. Commit in `site/` as `ajent-release-bot` with message `publish $TAG` and push to `gh-pages`.
   - It uses the default `GITHUB_TOKEN` (reading public releases needs no extra token).
8. `README.md`: what the repository is, the user install commands, the security model (Ed25519 verification of release checksums before publishing, GPG-signed metadata, the key URLs), and how to run `scripts/test-repo.sh` locally. User commands:
   - APT: `curl -fsSL https://pkg.ajent.social/gpg.key | sudo gpg --dearmor -o /usr/share/keyrings/ajent.gpg && sudo curl -fsSLo /etc/apt/sources.list.d/ajent.sources https://pkg.ajent.social/ajent.sources && sudo apt update && sudo apt install ajent`
   - DNF: `sudo curl -fsSLo /etc/yum.repos.d/ajent.repo https://pkg.ajent.social/ajent.repo && sudo dnf install ajent`
9. Open the PR in `ajent-social/packages`. After merge, enable Pages:
   - `gh api -X POST repos/ajent-social/packages/pages -f "source[branch]=gh-pages" -f "source[path]=/"` (this needs at least one publish, so run step 10 first if the branch is missing)
   - `gh api -X PUT repos/ajent-social/packages/pages -f cname=pkg.ajent.social -F https_enforced=true`
10. Before the first real ajent release exists, bootstrap `gh-pages` by running `publish.yml` via `workflow_dispatch` against a prerelease the maintainer authorizes, or by manually pushing `static/` to `gh-pages`. The second option publishes keys and instructions only, with no packages.

### Acceptance criteria

- In `ajent-social/packages`, `scripts/test-repo.sh` exits 0 locally and in `test.yml` CI. The debian, ubuntu and fedora installs print `ajent-fixture 0.0.7`, and pruning leaves 5 versions of each type.
- `shellcheck scripts/*.sh` is clean and `actionlint` passes on both workflows.
- `curl -fsSL https://pkg.ajent.social/gpg.key` returns the armored key once Pages is enabled. Record the output of `curl -sI https://pkg.ajent.social/ajent.sources`.
- Genuine-red: in `test-repo.sh`, corrupt `InRelease` after signing (append a byte). The debian `apt-get update` fails with a signature error. Restore it and report both outputs.
