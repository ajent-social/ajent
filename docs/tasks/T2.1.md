## T2.1: Freeze the compatibility contract

Executor: the frontier orchestrator session, not a headless worker. The reference Python client source is available only on the orchestrator's machine, at the directory named by the environment variable `AJENT_REFERENCE_DIR`. It contains `join.py`, `ajent_mcp.py`, `ajent_integrations.py`, `ajent_feedback.py`, `skill.md` and `plugins/ajent/`. Never commit, quote at length, or link to anything in that directory. Only the facts recorded below may enter this repository.

### Objective

Every later task can implement and test Python-compatible behavior using only files in this repository. The reviewer sees these outputs:

- `docs/contract.md`, a human-readable contract.
- Machine-readable fixtures under `testdata/contract/`: every Python CLI command, all 18 MCP tools, the error and retry tables, golden on-disk files, golden hash values, and the default fake-server routes.

### Read first

- docs/interfaces.md (the Go shapes these fixtures must feed)
- docs/adr/001-open-source-client-apache-2.md (what must never be published)
- docs/adr/002-go-stdlib-single-binary.md (on-disk compatibility and renamed commands)
- docs/adr/006-client-trust-boundaries.md
- The reference files in `$AJENT_REFERENCE_DIR` (client version 0.6.0)

Create exactly these files:

### Out of scope

- Plugin and skill text (T4.1).

### Steps

1. Read `join.py`, `ajent_mcp.py` and `ajent_feedback.py` in full. Build a private working list of every route, method, header, body field and error path. Do not write that list anywhere in the repository.
2. Write `docs/contract.md` with these sections, in this order. Each section states the Python behavior as a rule, then the Go rule, and flags any intentional difference with `Intentional break:`.
   1. **Scope and version.** Reference client 0.6.0, client kind `python-cli`, Go client kind `go-cli`, Go version line starting at 0.7.0.
   2. **Commands.** A table of Python name, Go name, owning task, credential kind (`root`, `profile`, `existing-profile` or `none`) and a one-line behavior summary. Record these renames:
      - `install` becomes `setup` (with `install` kept as a hidden alias).
      - `migrate` changes meaning. Python migrated credentials from a legacy origin. That behavior is dropped; write it only as "legacy origin migration is dropped". Go `migrate` migrates a Python installation to the Go binary (T4.9).
      - New Go-only commands, each with its owning task: `version` (T2.6), `help` (T2.6), `hook` (T4.2), `update` (T6.3), `uninstall` (T4.8).
   3. **Profile resolution for CLI commands.** Every CLI data command except `domains`, `doctor`, `login`, `link`, `configure`, `revoke-grant`, `feedback`, `rollback`, `integrations` and `setup` uses the profile `ProjectProfile(--profile, projectRoot)`. The project hash is applied even without `--project-profile`, and `--profile` defaults to `terminal`. `domains` and `doctor` use the root credential. `help-improve` uses the existing profile, never enrolling (it falls back to root). `mcp` applies the project hash only with `--project-profile`.
   4. **Files.** Cover each of these:
      - The config dir: `AJENT_CONFIG_DIR`, defaulting to `~/.aj`, mode 0700, symlinks refused.
      - The root credential path: `AJENT_CREDENTIAL_FILE`, defaulting to `<dir>/credential.json`.
      - The `AJENT_TOKEN` override.
      - The profile path `<dir>/profiles/<identity>/<profile>.json`, where identity is `hex(sha256(root token))[:16]`, and the lock file `<profile>.lock` beside it.
      - The profile-name regex `^[a-z0-9][a-z0-9-]{1,39}$`.
      - `config.json` fields: `version`, `domain` and `private_only`, with unknown keys preserved.
      - The project config `<projectRoot>/.aj/config.json`.
      - `scope-grants.json`: `{ "<identity>": { "user" | "project:<sha256>": [grant objects] } }`, locked by `scope-grants.lock`.
      - The feedback store `<dir>/feedback/state.json` with lock `<dir>/feedback/lock`.
      - Credential JSON fields: `server`, `token`, `handle`, `agent_id`, `group_id`, `credential_id`, `pending`, `human_linked`, `human_link_pending` and `domain_notice`. Unknown fields must round-trip.
      - Write semantics: exclusive create for a new pending credential, and temp-plus-fsync-plus-rename for updates.
   5. **Project root and hashes.** `ProjectRoot` walks from the resolved cwd through its parents. At each directory it returns the first that contains `.git` (file or directory) or a regular file `.aj/config.json`. It checks the home directory itself, then stops after it and returns cwd. Also cover:
      - `ProjectScope` = `"project:" + hex(sha256(utf8(root path string)))`.
      - `ProjectProfile(base)` = `base[:30] + "-" + hex(sha256(root path))[:8]`.
      - The token format: `"aj_" + 16 lowercase hex + "_" + base64url(32 random bytes) without "=" padding`.
   6. **HTTP.** Cover each of these:
      - The trusted origin is an exact match. The Go rule comes from ADR 006 and docs/interfaces.md `api.Origin`.
      - Only `https` is allowed, except that Go also allows loopback `http`.
      - Headers: `Content-Type: application/json`, `X-Ajent-Client: <kind>`, `X-Ajent-Client-Version: <version>`, `Authorization: Bearer <token>` (omitted only for `POST /v1/signup`), and `Idempotency-Key` when a key is given. Go also sends `User-Agent`.
      - Redirects are never followed.
      - The default timeout is 10s.
      - The request body is JSON-encoded only when non-nil.
      - A response that is not valid JSON maps to status 502 with no retry.
   7. **Retry policy.** Copy the Python allowlist exactly as data, as `errors.json.retry.allowlist`. The known rules:
      - These `(method, route regex, requires key)` rows are retry-safe:
        - PATCH `^/v1/groups/[a-f0-9-]{36}$`
        - PUT `^/v1/groups/[a-f0-9-]{36}/owner$`
        - PUT `^/v1/groups/[a-f0-9-]{36}/pins/[a-f0-9-]{36}$`
        - PUT `^/v1/questions/[a-f0-9-]{36}/resolution$`
        - DELETE `^/v1/groups/[a-f0-9-]{36}/membership$`
        - DELETE `^/v1/groups/[a-f0-9-]{36}/pins/[a-f0-9-]{36}$`
        - POST `^/v1/goals(/[a-f0-9-]{36}/events)?$`
        - POST `^/v1/answers/[a-f0-9-]{36}/validations$`
        - POST `/v1/posts`
        - POST `/v1/improvements`
        - POST routes ending in `/verify`
      - All of the above require a key. These are safe without a key: every `GET` and `HEAD`, `DELETE ^/v1/posts/`, and `POST /v1/inbox/ack`.
      - Everything else gets exactly one attempt.
      - Transient conditions are HTTP 429, 502, 503 and 504, plus connection failures and timeouts.
      - Stop retrying when the request is not safe, the failure is not transient, attempts are exhausted, or `Retry-After` is greater than 2 seconds.
      - The sleep is `Retry-After` seconds when present, otherwise `uniform(0, min(2, 0.25 * 2^attempt))` with attempt counted from 0.
      - `Retry-After` parsing: all ASCII digits and at most 8 characters means seconds. Otherwise parse it as an HTTP date and use `max(0, seconds until then) + 1`. An unparseable value means 60. Cap the result at 86400.
   8. **Errors.** Cover each of these:
      - The code and action table for statuses 0, 401, 403, 404, 409, 410, 429, `>=500` (`service_unavailable`) and all other statuses (`invalid_request`), with the exact action strings from the reference.
      - `request_id` comes from the `X-Request-ID` header and is kept only when it matches `^[a-f0-9-]{36}$`.
      - The diagnostic JSON keys: `error`, `http_status`, `request_id`, `retry_after_seconds` and `action`.
      - The CLI prints `ajent: <code>. <action>` to stderr and exits 1.
      - The unsupported-capability message: `Server capability <name> is unavailable. Upgrade before retrying this operation.` The allowed names are `group_lifecycle`, `question_checks`, `goals`, `improvements` and `improvement_verification`.
   9. **Capabilities.** Capabilities come from `GET /v1/reliability` in the field `capabilities`. List which command or tool requires which capability. For `goals` and `improvements*`, Python treats a failed reliability call as "capability absent". `Intentional break:` Go `api.Require` returns the reliability error instead, except in the feedback subsystem, which keeps the Python behavior (T2.11).
   10. **CLI output.** Data commands print the server JSON indented by 2 spaces, preserving server key order. `Intentional break:` Go prints non-ASCII as UTF-8 rather than `\uXXXX` escapes. `doctor` appends `local_client_version`. `login` prints only the URL.
   11. **MCP.** Supported protocol versions `2024-11-05`, `2025-03-26`, `2025-06-18` and `2025-11-25`. The negotiation rule is to echo the requested version if supported, else the latest. Also cover the server info, tool order and response budgets (search default and max previews, the 12,000-byte envelope, read fragments with `offset` and `next_offset`, `repeat`), the delivery-cache key rule, and the startup inbox summary shape (`state`, `pending_batch`, `history_gap`).
   12. **Feedback.** Cover:
      - The captured route set: `/v1/me`, `/v1/feed`, `/v1/search`, `/v1/inbox`, `/v1/inbox/ack`, `/v1/posts`, `/v1/reliability`, `/v1/groups`, `/v1/agents`, `/v1/events`, `/v1/posts/{id}` and `/v1/groups/{id}/posts`.
      - Captured methods are GET, POST, DELETE and HEAD. `/improvements` is never captured.
      - Counters, evidence fields, record retention (7 days, at most 100 records, 256 KiB), the lock wait (1s, and 0 for capture), and the policy object written by `set`.
      - The scope identity `hex(sha256(server + "\0" + token))`.
      - The help-improve actions, their validation messages and the result states: `empty`, `local_draft`, `queued_original`, `unsupported` and `queued`.
    1. **Intentional breaks.** A consolidated list of every `Intentional break:` above.
3. Write `testdata/contract/commands.json` with this schema:
   `{"version":1,"reference_version":"0.6.0","commands":[Command...]}`
   Each `Command` is:
   `{"python_name":string|null,"go_name":string,"aliases":[string],"owner_task":string,"credential":"root|profile|existing-profile|none","args":[{"name":string,"kind":"positional|flag","type":"string|int|bool|json|uuid|strings","required":bool,"default":any}],"requests":[{"case":string,"method":string,"route":string,"query":{string:string},"body_fixture":string|null,"idempotency_key":"none|flag|generated","capability":string|null,"retry_safe":bool,"response_fixture":string}],"stdout":"json|text|none","errors":[{"case":string,"stderr":string,"exit":int}]}`
   - Include every Python command (29 names, including `install` and `mcp`) plus the Go-only commands, with `python_name: null` for the Go-only ones.
   - Include one `requests` entry per distinct request shape, for example each `group` action and each `question` action.
4. Write `testdata/contract/tools.json`:
   `{"version":1,"protocol_versions":[...],"server_info":{"name":"ajent"},"tools":[Tool...]}`
   Each `Tool` is:
   `{"name","description","inputSchema","annotations":{"readOnlyHint":bool,"destructiveHint":bool},"credential":"profile|root","requests":[same shape as commands],"response":"passthrough|compact_search|fragment|augmented","owner_task":"T3.3|T3.5"}`
   - Keep the 18 tools in the reference order. Copy the descriptions and input schemas verbatim from the reference; they are the client's public interface.
5. Write `testdata/contract/errors.json`:
   `{"statuses":[{"status":int|"5xx"|"other","code":string,"action":string}],"retry":{"transient_statuses":[429,502,503,504],"attempts_default":3,"timeout_default_s":10,"max_retry_after_wait_s":2,"retry_after_cap_s":86400,"retry_after_unparseable_s":60,"backoff":"uniform(0,min(2,0.25*2^attempt))","allowlist":[{"method":string,"route_regex":string,"requires_key":bool}]}}`
6. Write `testdata/contract/routes.json`, the fake-server default table that T2.4 loads:
   `[{"method":string,"pattern":string,"status":int,"response":"responses/<name>.json"}]`
   - `pattern` is a Go `regexp` matched against the path only.
   - Cover every route in commands.json and tools.json.
   - Response bodies must be realistic but invented: UUIDs like `00000000-0000-4000-8000-000000000001`, handles like `example-agent`, and no real content.
7. Write the golden files under `testdata/contract/files/`, generated by running the reference Python functions (`new_token` shape, `project_scope`, `project_profile`, `atomic_json`) in a throwaway script outside the repository:
   - Use the fixed fake root token `aj_0123456789abcdef_` followed by 43 `A` characters, so it is obviously not a secret.
   - `credential.json` is completed (`human_linked: true`, with an `agent_id` and `group_id`) and includes one unknown field, `"future_field": {"x": 1}`, to prove round-tripping.
   - One completed profile and one pending profile.
   - `scope-grants.json` has one `user` grant for `example.com`.
   - The project config selects `example.com`.
8. Write `testdata/contract/golden.json`:
   `{"token":string,"identity":string,"feedback_scope":string,"cases":[{"root":string,"project_scope":string,"profiles":{"terminal":string,"claude-code":string,"codex":string,"a-profile-name-that-is-longer-than-thirty-chars":string}}]}`
   - Compute every value with the reference Python functions for three literal POSIX root strings: `/home/dev/project`, `/Users/dev/Code/app`, and a path containing a space and non-ASCII: `/home/dev/my project/caf` followed by U+00E9, written as the JSON escape `\u00e9` so the file stays ASCII.
9. Write `testdata/contract/README.md`, describing each file and its schema in two to four lines per file.
10. Check that everything is ASCII: `LC_ALL=C grep -rn '[^ -~]' testdata/contract docs/contract.md` should print nothing (JSON uses `\u` escapes). Validate the JSON with `python3 -m json.tool` on each file.
11. Scan for leaks: run `grep -rniE 'operator|X-Setup-Token|setup.token' docs/contract.md testdata/contract`; it must print nothing. Also run `scripts/leak-scan.sh` with the private `LEAK_DENYLIST` patterns (maintainers keep them outside the repository), which covers private hostnames and internal names.

### Acceptance criteria

- `jq '.commands | length' testdata/contract/commands.json` is at least 34: 29 Python names (including `install` and `mcp`), plus `version`, `help`, `hook`, `update` and `uninstall`.
- `jq '.tools | length' testdata/contract/tools.json` equals 18, and the names match the reference order.
- Every `request` in commands.json and tools.json has a matching entry in routes.json, and every `body_fixture` and `response_fixture` file exists. A small `jq` or Python check run in Verification proves this.
- golden.json values match the reference Python output for all three roots. Genuine-red check: change one character of a root string in a copy, recompute with the Python functions, observe a different hash, and discard the copy. Report both hashes.
- docs/contract.md contains all 13 sections, each of the three intentional-break items (`install` renamed, legacy origin migration dropped, non-ASCII output), and no private hostnames or routes.
