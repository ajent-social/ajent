## T5.11: Write the release publishing job

### Objective

When release-please creates a release (`release_created == 'true'`), the same `release.yml` workflow runs GoReleaser in the protected `release` environment. The run publishes archives, checksums, the Ed25519 signature, SBOMs, the notarized macOS binaries, the Homebrew cask, the Scoop manifest and the winget PR. It generates build-provenance attestations, dispatches the packages repository publish, and starts the channel verification workflow.

### Read first

- docs/tasks/T5.1.md (the existing `release.yml` and why publishing must live in it)
- docs/tasks/T5.3.md, T5.4.md, T5.5.md, T5.7.md, T5.8.md (the secrets each section needs)
- docs/tasks/T5.0.md and T5.14.md (secret names)
- docs/adr/004-release-signing.md

### Scope

Modify only `.github/workflows/release.yml`: add the `goreleaser` job after the T5.1 placeholder comment and replace that comment.

### Out of scope

- `.goreleaser.yaml`. `verify-release.yml` (T5.12). Anything in `ajent-social/packages`.

### Steps

1. Add this job (resolve every `uses:` to a commit SHA as in docs/tasks/T5.1.md step 3, with `# <tag>` comments; pin the GoReleaser version to the same `v2.x` used by T5.2):

   ```yaml
     goreleaser:
       needs: release-please
       if: needs.release-please.outputs.release_created == 'true'
       runs-on: ubuntu-latest
       environment: release
       permissions:
         contents: write
         id-token: write
         attestations: write
         actions: write
       steps:
         - uses: actions/checkout@<sha> # vX
           with:
             fetch-depth: 0
             ref: ${{ needs.release-please.outputs.tag_name }}
         - uses: actions/setup-go@<sha> # vX
           with:
             go-version-file: go.mod
         - uses: anchore/sbom-action/download-syft@<sha> # vX
         - uses: goreleaser/goreleaser-action@<sha> # vX
           with:
             distribution: goreleaser
             version: <GR>
             args: release --clean
           env:
             GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
             RELEASE_ED25519_KEY: ${{ secrets.RELEASE_ED25519_KEY }}
             HOMEBREW_TAP_TOKEN: ${{ secrets.HOMEBREW_TAP_TOKEN }}
             SCOOP_BUCKET_TOKEN: ${{ secrets.SCOOP_BUCKET_TOKEN }}
             WINGET_TOKEN: ${{ secrets.WINGET_TOKEN }}
             MACOS_SIGN_P12: ${{ secrets.MACOS_SIGN_P12 }}
             MACOS_SIGN_PASSWORD: ${{ secrets.MACOS_SIGN_PASSWORD }}
             MACOS_NOTARY_KEY: ${{ secrets.MACOS_NOTARY_KEY }}
             MACOS_NOTARY_KEY_ID: ${{ secrets.MACOS_NOTARY_KEY_ID }}
             MACOS_NOTARY_ISSUER_ID: ${{ secrets.MACOS_NOTARY_ISSUER_ID }}
         - uses: actions/attest-build-provenance@<sha> # vX
           with:
             subject-path: |
               dist/*.tar.gz
               dist/*.zip
               dist/*.deb
               dist/*.rpm
               dist/checksums.txt
         - name: Dispatch package repository publish
           env:
             GH_TOKEN: ${{ secrets.PACKAGES_TOKEN }}
             TAG: ${{ needs.release-please.outputs.tag_name }}
           run: gh api repos/ajent-social/packages/dispatches -f event_type=release-published -f "client_payload[tag]=$TAG"
         - name: Start channel verification
           env:
             GH_TOKEN: ${{ github.token }}
             TAG: ${{ needs.release-please.outputs.tag_name }}
           run: gh workflow run verify-release.yml --repo "$GITHUB_REPOSITORY" -f "tag=$TAG"
   ```

   The workflow-level `permissions: contents: read` from T5.1 stays. Job-level permissions widen only this job. `actions: write` is required for `gh workflow run`.
2. Never run this job on `pull_request`. The trigger stays `push` to `main` from T5.1.
3. If `verify-release.yml` does not exist yet when you run `actionlint`, that is fine: actionlint does not resolve workflow names. Mention it in the PR.
4. Dry-run the job logic without publishing on a branch. Temporarily add a `workflow_dispatch` job copy named `goreleaser-dryrun` that uses `args: release --snapshot --clean --skip=sign,notarize,publish` and no environment or secrets, and that skips the attestation, dispatch and verification steps. Push the branch, run it with `gh workflow run release.yml --ref <branch>`, and confirm it succeeds. Remove the dry-run job before opening the PR, and report the run URL.

### Acceptance criteria

- The release job fails before building when `.goreleaser.yaml` or the job environment mentions `extraKeyB64` (`grep -n extraKeyB64 .goreleaser.yaml` must find nothing, and `GORELEASER_*` or `LDFLAGS` must not set it). That test hook trusts an extra signing key and must never reach an official build (docs/tasks/T5.3.md step 4).

- `actionlint .github/workflows/release.yml` passes.
- The dry-run job in step 4 completed green. Report its URL.
- A review of the diff shows secrets referenced only in the `goreleaser` job, which has `environment: release`.
- The first real release (in E8) shows all of these: GitHub release assets (6 archives, `checksums.txt`, `checksums.txt.sig`, SBOMs, 4 packages), a commit in `homebrew-tap` and `scoop-bucket`, an open PR on `microsoft/winget-pkgs`, a `publish.yml` run in `ajent-social/packages`, a `verify-release.yml` run, and `gh attestation verify <archive> --repo ajent-social/ajent-client` succeeding. This item is checked at E8, not at merge.
- Genuine-red: in the dry-run branch, set `if: needs.release-please.outputs.release_created == 'false'` on a push that creates no release. The job then runs when it must not. Observe it, restore the condition, and report both run URLs.
