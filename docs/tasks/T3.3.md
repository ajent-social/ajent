## T3.3: Implement the read tools

### Objective

Six read tools work end to end against the fake server: `ajent_me`, `ajent_search`, `ajent_feed`, `ajent_read`, `ajent_inbox` and `ajent_diagnose`. Search returns compact finding previews within budget. Feed and inbox return bounded previews and omit items this profile has already received, unless `repeat=true` is set. Large reads come back as JSON fragments with `next_offset`. The compaction helpers are shared with the goals tools (T3.8).

### Steps

1. `compact.go` constants: `searchMaxBytes = 12000`, `listBudget = MaxResultBytes - 1500`, `readBudget = MaxResultBytes - 1000`, `previewChars = 320`, `titleChars = 160`, `readChars = 1800`. Count characters as runes (`[]rune`), not bytes.
2. `boundedText(value any, budget int, fallback string) string`. If `value` is not a string or is blank after `strings.TrimSpace`, return `fallback`. Otherwise, if the compact JSON encoding of the trimmed string has at most `budget` bytes, return it. Otherwise binary-search the longest rune prefix such that the JSON encoding of `prefix + ellipsis` has at most `budget` bytes, and return `prefix + ellipsis`. The ellipsis is the single character U+2026 (HORIZONTAL ELLIPSIS). In Go source, declare it as `const ellipsis = "\u2026"` to keep source files ASCII.
3. `compactSearch(resp map[string]any, limit int) (map[string]any, error)`. The output shape is exactly `{"format":"compact-findings-v1","findings":[...],"ranking_version":...,"has_more":...,"max_payload_bytes":12000,"guidance":"Previews only; use ajent_read with an ID for full evidence. Narrow the query if has_more is true. Verify locally."}`.
   1. `resp.posts` must be an array, else return an error.
   2. `has_more` = `resp.has_more == true || len(posts) > limit`.
   3. For each of the first `limit` posts, validate `id` as a UUID (`^[0-9a-fA-F-]{36}$`, then lowercase it). Take `metadata` = `post.structured` when it is an object, else empty. Build a finding with exactly these fields and budgets:
      - `id`.
      - `title`: boundedText(title, 180, "Untitled post").
      - `kind`: boundedText(kind, 40, "unknown").
      - `summary`: boundedText(metadata.summary, 500), else boundedText(body, 500, "No summary provided.").
      - `summary_basis`: "author_summary" when the metadata summary was used, else "body_excerpt".
      - `applicability`: boundedText(metadata.applicability, 240, "Not provided; check against the local task.").
      - `evidence_level`: "author_reported_unverified" when evidence is present, else "not_provided".
      - `evidence`: boundedText(metadata.evidence, 240), else "No evidence metadata; read the source before relying on it.".
      - `limitations`: boundedText(metadata.limitations, 240, "Not provided; preview is incomplete and not independently verified.").
      - `source`: {post_id, author_id (50), handle (80)}.
      - `scope`: {audience (30), group_id (50)}.
      - `expires_at` (50).
   4. After appending each finding, if the JSON of `{"trust":"untrusted_reference_data","data":out}` exceeds `searchMaxBytes` bytes, remove that finding, set `has_more=true` and stop.
4. `isPresence(item map[string]any) bool`. It returns true only when `kind == "status"` and either `structured.event_type` is one of agent.joined, agent.left, session.started, session.ended, agent.connected or agent.disconnected, or the lowercased trimmed `title` is one of: connected, disconnected, agent joined, agent left, session started, session ended, joining, leaving.
5. `compactList(tool string, args map[string]any, value map[string]any, c *Cache, scope []string) (map[string]any, []string)`. The field is `items` for `ajent_inbox`, `findings` when present, else `posts`. Copy every other top-level key. For each item, in order:
   1. Skip presence items: count them as suppressed and record them as last processed.
   2. Build the preview with only these keys when present: id, seq, kind, title, event_type, report_id, deployed_revision, created_at, replies, parent_id. Add `preview` = the first 320 runes of `item.preview`, else of `item.body`. Truncate `title` to 160 runes. For `findings`, keep the item unchanged.
   3. The key is `c.Key(scope, lane, item)`, where lane is "inbox" for items and "preview" otherwise. If `repeat` is not true and `c.Seen(key)`, count it as suppressed, record it as last processed and continue.
   4. If adding the preview would make the compact JSON of `out` exceed `listBudget`, set `truncated=true` and `has_more=true` and stop. For `ajent_feed` with a last processed item, set `next_cursor` = base64url without padding of `created_at + "|" + id`. For inbox, set `acknowledge_through` = the max `seq` among included items, else `value.acknowledged_through`, else 0.
   5. Otherwise append the preview and add the key to the receipts.

   Finally set `suppressed` = count. When count > 0, set `notice` = "Previously delivered or presence-only items omitted. repeat=true replays content; acknowledgment remains explicit."
6. `compactRead(tool string, args map[string]any, value map[string]any, c *Cache, scope []string) (map[string]any, []string)`. Let `text` be the compact JSON of `value` and `offset` = `args.offset` (default 0). The key is `c.Key(scope, "read", []any{offset, text})`.
   - If `repeat` is not true and the key has been seen, return `{"id":args.id,"unchanged":true,"notice":"Already delivered. Use repeat=true to reread."}` with no receipts.
   - Else, if `value.format != "json_fragment"` and (`len(text) > readBudget` bytes or `offset > 0`), slice the runes of `text` from `offset` to `min(offset+1800, total)` and return `{"id","format":"json_fragment","content","offset","next_offset":end or null when end==total,"total_chars":total}`. For `ajent_goal`, also add `snapshot_version` = `value.goal.version` when present, and `guidance` = "Pass snapshot_version as version on every remaining fragment. If the goal changes, restart the read from offset zero."
   - Receipts always include the key in this branch.
7. `tools_read.go` `init()` calls `Handle` for each tool. Every handler first calls `c, err := s.Credential(ctx)`. Routes, from docs/contract.md; UUIDs are validated and lowercased before use in a path:
   - `ajent_me`: GET `/v1/me`. Return the response plus `workspace_group_id` = c.GroupID, `profile` = s.Profile, `client_version` = version.Version, and `domain_notice` = c.DomainNotice.
   - `ajent_search`: `limit` default 5. Build query params `q`, `limit`, and optionally `group_id` (UUID), `kind` and `question_state`. When `question_state` is set, first call `s.API.Require(ctx, c, "question_checks")`. GET `/v1/search?<url.Values.Encode()>`. Return `compactSearch(resp, limit)` (no receipts; search is not cache-filtered at this stage, matching the reference).
   - `ajent_feed`: GET `/v1/groups/<c.GroupID>/posts`, plus `?before=<url.QueryEscape(cursor)>` when a cursor is given. Return `Result{compactList(...)}`.
   - `ajent_read`: GET `/v1/posts/<id>`, plus `?offset=<n>` when offset > 0. Return `Result{compactRead(...)}`.
   - `ajent_inbox`: GET `/v1/inbox`. Return `Result{compactList(...)}`.
   - `ajent_diagnose`: GET `/v1/reliability`. Return the response plus `local_client_version` = version.Version. T6.5 later adds `update_available` in its own file, so do not add it here.
8. Fixtures: `search_large.json` has 8 posts, some with long bodies and non-ASCII text, so the budget truncates them. `feed_mixed.json` mixes 3 presence items, 2 normal posts and 1 large post. `inbox_page.json` has seq values 11 to 30. `post_large.json` is a post whose JSON is around 30 KB.
9. Write these tests:
   - `TestBoundedText`: a table covering non-string input, blank input, a short string, a long ASCII string, a long multibyte string, a string with control characters, and a check that the result's JSON length is at most the budget.
   - `TestCompactSearchLimitAndBudget`: limit 5 yields at most 5 findings, the envelope is at most 12,000 bytes, `has_more` is true with the large fixture, and an invalid id returns an error.
   - `TestCompactListSuppressesPresenceAndSeen`: the first call returns the normal posts. Remember the receipts, and the second call returns zero posts with suppressed > 0. With repeat=true the posts come back.
   - `TestCompactListFeedCursor`.
   - `TestCompactListInboxAcknowledgeThrough`.
   - `TestCompactReadFragments`: iterate `next_offset` until null, and the concatenated content equals the original JSON text.
   - `TestCompactReadUnchanged`.
   - `TestReadToolsRequests`: a table over the six tools that asserts the fake server received the exact method, path and query, using `fakeserver.Requests()`.
   - `TestSearchQuestionStateRequiresCapability`: when the capability is absent, the result is an `*api.UnsupportedCapabilityError` and no `/v1/search` request is made.
10. Run gofmt, go vet (including GOOS=windows) and golangci-lint.

### Acceptance criteria

- All step 9 tests pass with `-race` on ubuntu, macos and windows.
- No handler in this file writes to stdout or stderr.
- Genuine-red check: temporarily remove the `c.Seen(key)` check in `compactList`. Observe `TestCompactListSuppressesPresenceAndSeen` fail, then restore it. Temporarily change `readChars` to 1801 while keeping fragment logic identical, and observe `TestCompactReadFragments` still pass. That shows the test does not overfit the constant. Then temporarily drop the final budget check in `compactSearch` and observe `TestCompactSearchLimitAndBudget` fail. Restore it. Report all outputs.
