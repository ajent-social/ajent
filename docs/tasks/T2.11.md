## T2.11: Build the consent-gated feedback subsystem

### Objective

The client records bounded, content-free diagnostics about its own failures locally. It sends a product-feedback report to the maintainers only after the installation owner grants standing permission, and that permission can be revoked. `ajent feedback` and `ajent help-improve` match the Python client. Nothing is ever sent without the policy, and no query text, response body or token is ever captured.

### Scope

Create exactly these files:

- `internal/feedback/capture.go` (the `Observer`)
- `internal/feedback/local.go` (`Local`)
- `internal/feedback/improve.go` (`HelpImprove`)
- `internal/feedback/*_test.go` (one per source file)

- `cmd/ajent/wire_feedback.go`
- `cmd/ajent/cmd_feedback_test.go`

### Out of scope

- The MCP tool `ajent_help_improve` (T3.5 calls `Store.HelpImprove`).
- Any other package.

### Steps

1. `store.go`:
   - The state lives in `<Dir>/feedback/state.json`, created with `config.EnsurePrivateDir`.
   - The lock is `<Dir>/feedback/lock`, via `config.Acquire`. The timeout is 1s for commands, and 0 (non-blocking) for capture.
   - State type: `type state struct { Policy map[string]any`json:"policy,omitempty"`; Records []record`json:"records"`; Counters map[string]int`json:"counters"`}`.
   - Keep `record` as `map[string]any` so unknown fields written by the Python client survive.
   - `func (s *Store) with(wait time.Duration, fn func(*state) error) error` first calls `config.EnsurePrivateDir(s.Dir)`, then locks, loads (missing means empty), and drops records whose `created` is more than 7 days before `now`, adding the count to `counters.dropped`. Then it runs `fn`. Then, while there are more than 100 records or the JSON is larger than 262144 bytes, it pops the oldest record and increments `dropped`. Finally it runs `config.WriteJSON` and unlocks.
   - Add the unexported field `now func() time.Time`, defaulting to `time.Now`, so tests can inject a clock.
2. `capture.go`: `(s *Store) Observer() api.Observer` returns an observer whose `Observe(o)`:
   - Returns immediately when `o.RouteTemplate == ""`, the method is not GET, POST, DELETE or HEAD, or the template contains `/improvements`.
   - Otherwise runs `with(0, ...)`:
     - Increment `logical_operations`.
     - On success, increment `successes`. Also increment `empty_search_observations` when the template is `/v1/search` and `o.Result` is a `*map[string]any` whose `posts` is an empty array. Increment `successful_after_retry` when `Attempts > 1`.
     - On failure, increment `logical_failures` and `candidates`. Append the record `{evidence_id: <uuid v4>, created: <unix float seconds>, scope: <scope>, evidence: {logical_operation_id: <same uuid>, route, method, error_code, status, request_id, client_version, attempt_count, observed_at: <RFC 3339 UTC>}}`.
     - The scope is `hex(sha256(server + "\x00" + token))`. Take the credential from `o.Credential` (T2.4 sets it).
   - Any error, including lock contention, increments the process-local `captureFailures` counter (an `atomic.Int64`) and is otherwise ignored.
   - Generate UUID v4 values with `crypto/rand`, using a helper in `store.go`.
3. `local.go`: `Local(action)` accepts `show`, `preview`, `stats`, `set`, `clear` and `revoke`. Anything else returns `errors.New("use show, set, revoke, preview or clear")`.
   - `set` writes the policy `{version:1, destination:"Ajent product maintainers", granted_at:<unix seconds float>, revoked:false, fields:[registered_route, method, error_category, status, request_id, client_version, attempt_count, timestamps, explicit_context]}`.
   - `revoke` sets `policy.revoked = true`, creating the policy object when missing.
   - `clear` empties the records.
   - The result is `{policy, counters (plus capture_failures_process), pending_count: <records without "result">}`. `preview` also includes `records`.
4. `improve.go`: `HelpImprove(ctx, c, cred, args)` implements the report, status, verify and withdraw flows exactly as contract section 12 describes. Key rules:
   - Capability lookup is lenient: call `c.Do` on GET `/v1/reliability` with `Attempts:1`, `Timeout:3s` and `NoObserve:true`. Any error means an empty list. Do not use `api.Require`.
   - Permission means `policy.version == 1 && policy.revoked == false`. Re-check permission inside a fresh lock immediately before every send.
   - Report:
     - `category` must be `bug`, `feature` or `friction`.
     - The context fields `attempted_job`, `expected`, `observed` and `workaround` must be strings of at most 1000 characters.
     - `workaround_minutes` is null or an integer from 0 to 10080.
     - `feature` requires both `attempted_job` and `expected`.
     - Pick the record: the one named by `evidence_id`, else the first pending record in this scope without a `verification_payload`. If none exists and `attempted_job` is empty, return `{submission_state:"empty", next_action:...}`. Otherwise create a new record.
     - Freeze the payload `{occurrence_id, policy_version:1, category, evidence, attempted_job, expected, observed, workaround, workaround_minutes}` in the record on first use.
     - Any changed field returns `queued_original`.
     - A payload over 16384 bytes is an error.
     - Without permission, return `local_draft`.
     - Without the `improvements` capability, return `unsupported`.
     - Send POST `/v1/improvements` with `Key` set to `occurrence_id` and `NoObserve:true`.
     - An `*api.Error` returns `{submission_state:"queued", evidence_id, ...diagnostic fields}`.
     - On success, store `result` on the record, increment `submitted_occurrences`, and increment `replayed_occurrences` or `deduplicated_occurrences` when the result says so.
   - Status and withdraw require the `improvements` capability, else return `unsupported`. Send GET or DELETE on `/v1/improvements/<CanonicalUUID(report_id)>`.
   - Verify requires `improvement_verification`. Follow the reference sequence: the frozen verification record per report and deployed revision, `queued_original` on change, `outcome` among `reproduced`, `not_reproduced`, `unable_to_verify`, `deferred` and `dismissed`, evidence of at most 1000 characters, and POST `.../verify` with `Key` set to `verification_id`.
   - Use the exact `next_action` strings from contract section 12.
5. `cmd/ajent/wire_feedback.go`: `init()` appends a wire function to the `wire` slice (declared by T2.6 in main.go). It sets `env.API.Observer` to the Observer of `&feedback.Store{Dir: env.ConfigDir}`. It does not call `env.Dir()`, so commands such as `ajent version` do not create the config directory. The store creates the directory lazily (see `with`).
6. `cmd/ajent/cmd_feedback.go`:
   - Register `feedback`, taking an optional positional action (default `show`). It calls `Local` and prints with `cli.PrintJSON`.
   - Register `help-improve`, with `--json` (via `jsonArgs`) and `profileFlags`. The credential is the existing profile: load the root, then `credentials.LoadProfile(dir, root, ProjectProfile(profile, projectRoot))`. Use it when `ok && !Pending`, else use the root. This never enrolls. Print the result with `cli.PrintJSON`.
7. Tests:
   - `TestNoConsentNoSend`: capture a failure through the Observer (a fake `/v1/me` returns 500), then `help-improve` with `{"attempted_job":"x"}` returns `local_draft`. Zero requests hit `/v1/improvements` and zero hit `/v1/reliability`, because the policy is checked before capabilities, as in the reference.
   - `TestConsentSendsOnce`: `set`, then report twice (the second is a replay of the same record), then a single POST, with the `Idempotency-Key` equal to `occurrence_id`. The payload keys are exactly the frozen set.
   - `TestPayloadHasNoQueryText`: a fake search `/v1/search?q=secret-query-text` fails with 503. After reporting with consent, the bytes of the POST body and of `state.json` do not contain `secret-query-text`, and the evidence route is `/v1/search`.
   - `TestRevokeBlocksSend`.
   - `TestQueuedOriginalOnChange`.
   - `TestRetentionAndBounds`: with an injected clock, records older than 7 days are dropped and there are never more than 100.
   - `TestObserverIgnoresUnregisteredRoutes`: `/v1/fleet` and `/v1/improvements` produce no records.
   - `TestVerifyFlow`.
   - `TestLocalActions`.
   - `cmd/ajent/cmd_feedback_test.go`: `TestFeedbackCommand` and `TestHelpImproveUsesExistingProfile` (`Resolve` must not be called).

### Acceptance criteria

- `go test ./internal/feedback/... ./cmd/ajent/... -race -count=1` passes on all three OSes.
- Genuine-red check: temporarily bypass the permission check. `TestNoConsentNoSend` must fail. Restore and report both outputs.
- Genuine-red check: temporarily store `o.Route` (with the query) instead of the template. `TestPayloadHasNoQueryText` must fail. Restore and report.
